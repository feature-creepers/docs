# Brief: make this project's CI fast, cheap and solid

You are the coding agent of a solo developer who built and maintains a CRM web application with many modules, hosted on GitHub. He writes code fast, partly generated by tools and agents. His main problem is that **CI is slow**: every push and every pull request waits a long time for its checks.

Your mission: **measure where CI time goes, cut it, and leave behind a CI setup he can understand, run, rebuild and roll back alone.** That includes, if the numbers justify it, a small fleet of self-hosted runners on OVHcloud VPS (cheap, effective, and in France, which suits a French group).

He is technical and curious, but not a professional developer. So **every decision you make comes with its reason**, in plain words, both in your messages and in the documentation you leave. Talk to him in the language he uses with you (likely French). Code, comments and docs can stay in English if that is the repo's habit.

This brief is long on purpose. Read it all before you start. Sections 3 to 9 are the work, in order. Section 12 is your definition of done. Appendices A and B hold the scripts to adapt.

---

## 0. How to work

1. **Measure first, change second.** No optimisation without a baseline number, and none without a number after. You will run an audit script (Appendix A.1) before and after each phase.
2. **One phase, one pull request.** Each PR states its goal, what changed, the before/after numbers, and how to undo it. Small PRs are easier for him to review, and a regression is easy to pin on its cause.
3. **Ask before anything that costs money, touches an account, or is hard to undo:** ordering a VPS, creating an Object Storage bucket, changing branch rules, adding secrets, turning on self-hosted runners. Give him the exact clicks or commands, explain what each one does, and wait for his go.
4. **Every change has a one-line way back.** For example, the switch to self-hosted runners is a single repository variable. Deleting it returns everything to GitHub-hosted runners.
5. **Never put a secret in a repository**: no password, private key, token or auth key, in any file or commit. Public SSH keys are fine. If a secret is ever committed, *rotate it*. Rewriting git history isn't enough.
6. **Everything on a machine comes from a script that can be re-run safely** (idempotent). Nothing gets set up by hand on a server, because what was done by hand is lost at the next rebuild.
7. **When in doubt, check more, not less.** A CI that wrongly skips a check lets a broken change merge. A CI that wrongly runs one only costs minutes.
8. **Don't guess versions or hashes.** Look up current action versions, runner releases, image digests and prices at the source (links in Appendix C). Things marked `<…>` in the templates are placeholders you must fill in.

## 1. Context to collect first

Before proposing anything, find out, from the repo and by asking him:

- **Stack:** languages, frameworks, package manager(s), lockfiles, test runners, linters, type checkers, build tools. Is it a monorepo (workspaces, packages) or one app with internal modules?
- **What CI does today:** every file in `.github/workflows/`, every job, every step, triggers, matrices, services (database, cache, queue), browser tests, Docker builds, deployments.
- **Generated code:** what generates it (ORM client, API client from OpenAPI, GraphQL types, translations, scaffolding), whether the output is committed, how big it is, and whether CI checks that it is up to date.
- **Repository facts:** private or public, personal account or organisation, GitHub plan (Free, Pro, Team), and whether branch protection or rulesets exist.
- **How he works:** pushes per day, PRs per day, how often he pushes to `main` directly, whether he uses draft PRs, whether an agent pushes for him.
- **Deployment:** where and how the app deploys, and which secrets that needs.

Write it down as the first section of the audit report (section 3).

## 2. Principles (the "why" behind everything)

These are the ideas the rest of this brief applies. Explain them to him as you apply them.

| # | Principle | Why |
| --- | --- | --- |
| P1 | **Measure, then optimise the biggest bar.** | Intuition about slow CI is usually wrong. Install time, queue time or one slow test file often dominate. |
| P2 | **Don't run what didn't change.** | Most PRs touch one or two modules. Re-checking all of them is the largest waste in a modular codebase. |
| P3 | **Don't redo what was already done.** Cache dependencies, tools and task results keyed by their inputs. | A task whose inputs haven't changed will give the same result. Replaying it takes seconds. |
| P4 | **Run independent work at the same time**, but only as much as the machine's memory allows. | Parallelism is free speed until the machine swaps or kills a process. Then it is slower than running in sequence. |
| P5 | **Start slow things early.** Boot the database container *before* installing dependencies. | Waiting in parallel costs nothing. Waiting in sequence costs the sum. |
| P6 | **Report every failure in one run.** | Fix-push-wait-fix-push loops are the slowest CI of all. |
| P7 | **Cancel what's outdated.** A new push to a PR cancels that PR's running checks. | Nobody needs results for a commit that no longer exists. |
| P8 | **One stable required check.** | Branch rules need a check name that always reports. Skipped or missing checks either block merges forever or wave them through. |
| P9 | **Warm machines beat cold machines.** | GitHub-hosted runners start empty every time. A self-hosted runner keeps its tools, images, browsers and caches between jobs. |
| P10 | **Machines are cattle, described by scripts.** | Any runner can die, be rebuilt from scratch in about 30 minutes, and come back identical. |
| P11 | **A CI runner that runs PR code holds no secret.** | Any dependency's install script, or any test, runs with the runner's rights. Deploy elsewhere. |
| P12 | **Pin everything that can move:** action versions by commit SHA, container images by digest, runner images by version, tool versions in files. | A floating tag that changes under you breaks CI for reasons unrelated to your change, or silently changes what you trust. |
| P13 | **Same command locally and in CI.** | If he can run the exact CI check before pushing, he pushes fewer broken commits. Every avoided red run saves a whole CI cycle. |

## 3. Phase 1: Measure (audit)

### 3.1 Run the audit script

Add `tools/ci_audit.py` (Appendix A.1). It only reads data, through the GitHub CLI. Run it on the main CI workflow for the last 50 to 100 runs:

```sh
gh auth status                      # must be logged in with read access to the repo
python3 tools/ci_audit.py OWNER/REPO --workflow ci.yml --runs 100
```

It prints, per event (`pull_request`, `push`):

- **wall time per run** (median, p90);
- **queue time per job**: how long jobs waited for a runner. High queue times mean there aren't enough runners.
- **duration per job**, and **the slowest steps**, with their share of the job;
- **conclusions**: the share of failures and cancellations;
- **load**: runs per day and job-minutes per day. This is the basis for the cost comparison in 7.1.

If there are several workflows, run it for each.

### 3.2 Read the logs of a few slow runs

Numbers say *where* time goes, and logs say *why*. Look for:

- Dependency installs that download everything each time (no cache, or a cache key that never hits).
- A job repeated per module or per matrix entry, each redoing checkout, toolchain setup and install.
- `push` *and* `pull_request` both triggering for the same commit, so it runs twice.
- Tests that wait on `sleep`, real network calls, or a database with durable writes (fsync).
- Linters or type checkers walking generated code.
- Browser tests that download browsers every run, or run everything serially.
- Docker images rebuilt from scratch.
- Jobs without `timeout-minutes`: a hung job holds a runner for up to 6 hours, the default.

### 3.3 Write the audit report

Post it as an issue (or a Markdown file in the PR of phase 2) with:

1. Context (section 1).
2. Baseline numbers (the audit output).
3. The top 5 time sinks, each with its estimated gain.
4. The plan: which phases of this brief apply, in which order, and what you need from him (accounts, money, decisions).

Ask him to agree with the plan before phase 2.

## 4. Phase 2: Workflow hygiene (quick wins, still on GitHub-hosted runners)

These are low-risk and usually save a lot. Apply them in one PR. Appendix A.2 shows them all in one workflow.

### 4.1 Trigger once per change

```yaml
on:
  pull_request:          # every PR, on its merge commit with the base branch
  push:
    branches: [main]     # main only: branch pushes are covered by their PR
```

**Why:** `on: push` for every branch plus `on: pull_request` runs CI twice for each commit pushed to a PR.

### 4.2 Cancel outdated runs

```yaml
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}
```

**Why:** on a PR, only the latest push matters. On `main`, a started run finishes (it tells whether `main` is healthy), and a newer push *replaces* a run that hasn't started yet: GitHub keeps one pending run per group.

### 4.3 Timeouts, least privilege, shallow checkout

```yaml
permissions:
  contents: read           # the job's token can read the code, nothing else
jobs:
  ci:
    timeout-minutes: 30    # about 2x the normal duration; the default is 6 hours
    steps:
      - uses: actions/checkout@<sha> # <version>
        with:
          fetch-depth: 2           # enough to diff a PR's merge commit with its base (section 5)
          persist-credentials: false  # don't leave the token in .git/config for later steps
```

**Why:** a hung test should fail in 30 minutes, not hold a runner for 6 hours. A token that can only read can't be abused by a malicious dependency. A full history clone of a big repo costs time for nothing.

### 4.4 Dependency caches

Use the official setup actions' built-in cache, keyed by the lockfile:

- Node: `actions/setup-node` with `cache: npm | pnpm | yarn` ([docs](https://github.com/actions/setup-node#caching-global-packages-data)).
- Python: `actions/setup-python` with `cache: pip | poetry`, or `astral-sh/setup-uv` with `enable-cache: true`.
- PHP: cache Composer's cache dir with `actions/cache` keyed by `composer.lock`.

Install with the **frozen lockfile** (`npm ci`, `pnpm install --frozen-lockfile`, `yarn install --immutable`, `composer install --no-interaction --prefer-dist`, `uv sync --frozen`). **Why:** CI must test exactly what's locked, and fail if the lockfile is out of date, instead of silently resolving new versions.

### 4.5 Pin actions and the runner image

- Use `runs-on: ubuntu-24.04` (or the newest version GitHub lists), not `ubuntu-latest`. **Why:** `-latest` moves to a new OS on GitHub's schedule, and breaks things on a day you didn't choose.
- Pin every third-party action by full commit SHA, with the version as a comment: `uses: actions/checkout@<40-char-sha> # v5.0.0`. Find the SHA with `gh api repos/actions/checkout/commits/v5.0.0 --jq .sha`, or use a pinning tool such as `pinact`. **Why:** a tag can be moved to malicious code, and a SHA can't ([GitHub's hardening guide](https://docs.github.com/en/actions/security-for-github-actions/security-guides/security-hardening-for-github-actions#using-third-party-actions)).
- Add Dependabot for `github-actions` (Appendix A.8), with **grouped** updates. **Why:** pinned SHAs need updating. Grouping makes one PR a week instead of ten, and so ten times fewer CI runs.

### 4.6 Report everything in one run

Configure tools to continue past failures: `--continue` (Turborepo), the default in Nx, `pytest` without `-x`, or a small "collect failures, exit at the end" wrapper (Appendix A.4, variant C). **Why:** P6.

### 4.7 One required check, always reporting

Branch rules (section 9) require a check by **name**. Two traps:

- **A workflow that doesn't run** (filtered out by `paths:` / `paths-ignore:`) never reports, so a required check stays "expected" forever and the PR can't merge.
- **A job skipped by an `if:` counts as passed.** If the required job is skipped, the PR merges unchecked.

Two safe patterns:

1. **One job named `CI` that always runs,** with no job-level `if:` and no `paths:` filter. It decides *inside* what to check (section 5). This is the recommended pattern on self-hosted runners, where one job per machine is the unit of capacity.
2. **Several jobs plus a final aggregator job** that `needs:` all of them, runs `if: always()`, and fails if any of them failed or was cancelled. Only the aggregator is required:

```yaml
  ci-ok:
    name: CI
    if: always()
    needs: [lint, test, e2e]
    runs-on: ubuntu-24.04
    steps:
      - run: |
          echo '${{ toJSON(needs) }}' | jq -e 'all(.[]; .result == "success" or .result == "skipped")'
```

### 4.8 A summary humans can read

Write the scope (what was checked and why) and a short result table to `$GITHUB_STEP_SUMMARY`. **Why:** he should see in one glance what ran, what was replayed from cache, and what failed, without scrolling through 5,000 lines of log.

### 4.9 Lint the workflows themselves

Run [`actionlint`](https://github.com/rhysd/actionlint) (catches expression and syntax mistakes) and [`shellcheck`](https://www.shellcheck.net/) on every script, and optionally [`zizmor`](https://github.com/zizmorcore/zizmor) (security issues in workflows). Make them part of the checks. They take seconds.

## 5. Phase 3: Do less (check only what a change affects)

This is usually the biggest gain for a project with many modules.

### 5.1 Classify every run into a mode

A `Scope` step (script in Appendix A.3) looks at the files the change touches and picks one mode:

| Change | Mode | What runs |
| --- | --- | --- |
| Push to `main`, scheduled run, manual run, merge queue | `full` | Everything |
| PR touching a **global file** (CI workflow and scripts, lockfiles, toolchain versions, root configs, test service images, files that tests read from outside their module) | `full` | Everything |
| PR where **every** file is documentation (`*.md`, `docs/**`) and none is global | `docs` | Docs and format checks only, with minimal install |
| Any other PR | `affected` | The modules changed, **plus the modules that depend on them**, plus repository-wide checks |

**Why each rule exists:**

- **`main` always runs full,** so that two PRs that pass separately but break together are caught right after the merge, on `main`, and the merged result is always fully checked.
- **Global files run full** because they change what *every* check reads, but no module "owns" them, so affected-detection can't see their impact.
- **Global files are tested before the docs-only rule.** A Markdown file can be global, for example a document a test parses, and a lockfile dropped into `docs/` still changes what the package manager reads in that folder.
- **Match global files case-insensitively,** since Windows and macOS disks are case-insensitive: `Package-Lock.json` is the same file there. Over-matching only costs a full run.
- **The PR is compared on its merge commit:** `actions/checkout` on `pull_request` checks out `refs/pull/N/merge`, so `HEAD^1` is the tip of the base branch and `HEAD` is the result of merging. `fetch-depth: 2` is enough for this.

### 5.2 Affected detection: use the dependency graph

- **JavaScript/TypeScript monorepo:** use a task runner that knows the workspace graph and caches by input hash. Two common choices:
  - [Turborepo](https://turborepo.com/docs): `turbo run lint test build --filter='...[HEAD^1]'` (the packages changed since `HEAD^1` and everything that depends on them). See [filtering](https://turborepo.com/docs/crafting-your-repository/running-tasks#using-filters) and [`--affected`](https://turborepo.com/docs/reference/run#--affected).
  - [Nx](https://nx.dev/ci/features/affected): `nx affected -t lint test build --base=HEAD^1 --head=HEAD`.
- **One app with internal modules** (common for CRMs in PHP, Python, Ruby): there's no workspace graph. Do it by folder: the scope script can output the list of changed modules (`MODULE_PATTERNS` in A.3), and the check runs those modules' test suites. **A shared module that others import (core, auth, shared models) goes on the global list,** because without a dependency graph, a change to it must check everything. If he has more than about 10 modules and a growing shared layer, suggest moving to a real workspace structure later.
- **Don't use GitHub's `paths:` filters for this.** They decide whether a *workflow* runs, not what it checks, and they break required checks (4.7). Do the classification in a step.

### 5.3 The "hidden input" trap

Affected detection assumes a module's tests read only that module and what it depends on. When a test reads a file outside (a root config, a shared fixture, a schema in `docs/`, the CI workflow itself), a change to that file selects nothing, and the test that should catch it doesn't run. Then `main` breaks after the merge.

- Declare such files as task inputs (Turborepo: `inputs` with `$TURBO_ROOT$/path`; Nx: `namedInputs`), **and** put them on the scope's global list.
- Write a small check that fails if a task input outside its package isn't on the global list. That keeps the two lists in sync as the code grows.
- Make the **CI workflow and its scripts inputs of every test task**, so a change to how CI starts the database reruns every test instead of replaying old results.

### 5.4 Test the scope logic itself

The scope script is code that decides what gets checked, so a bug in it lets broken changes through. Appendix A.3 includes a test script that runs it on invented changes and checks the mode. Run that test in every CI run (it takes under a second). The scope script is on its own global list, so a change to it triggers a full run.

### 5.5 Draft PRs (optional)

If he pushes a lot of work-in-progress, consider running only fast checks while a PR is a draft, and the full scope when it's marked ready (`types: [opened, synchronize, reopened, ready_for_review]`). A draft can't merge, so that's safe. Explain the tradeoff, and let him choose.

## 6. Phase 4: Make the work itself faster

### 6.1 Task-result caching

With a task runner (Turborepo/Nx), every task result is cached by a hash of its inputs. A rerun with nothing changed prints "cache hit" for each task.

- **On GitHub-hosted runners:** keep the task cache folder in `actions/cache`. Split it into `actions/cache/restore` + `actions/cache/save`, so you can:
  - **restore** with `key: tasks-${{ runner.os }}-${{ github.sha }}` and `restore-keys: tasks-${{ runner.os }}-` (the latest cache of this PR, or else of `main`);
  - **save even when a check failed** (`if: ${{ !cancelled() }}`). Otherwise one failing test throws away the results of the 99 tasks that passed, and the next push redoes them all.
  - **prune** entries older than about 14 days before saving, so the cache doesn't grow forever.
- **GitHub cache scoping rules** ([docs](https://docs.github.com/en/actions/writing-workflows/choosing-what-your-workflow-does/caching-dependencies-to-speed-up-workflows#restrictions-for-accessing-a-cache)): a PR can read caches of its base branch (`main`) but not of other PRs, and `main` can't read a PR's cache. Entries unused for 7 days are evicted, and the default size limit per repo is 10 GB. Large Docker layers or browser downloads can evict the task cache.
- **On self-hosted runners**, a **shared remote cache** in object storage beats all of this (section 7.8).

### 6.2 Test speed

- **Database tests:** run the database in a container with **data on tmpfs** and **durability off**. It is a throwaway database, so losing it on a crash costs nothing:
  `postgres -c fsync=off -c synchronous_commit=off -c full_page_writes=off` and `--tmpfs /var/lib/postgresql`. That often makes database-heavy suites 2 to 5 times faster. (MySQL/MariaDB: `--innodb-flush-log-at-trx-commit=0 --skip-log-bin` and tmpfs on `/var/lib/mysql`.)
- **Build the schema once, copy it per test file:** create a template database once (migrations run once), then give each test worker its own copy (`CREATE DATABASE x TEMPLATE tpl` in Postgres), instead of migrating per test.
- **Run tests in parallel** within a runner: Vitest/Jest workers, `pytest -n auto` ([pytest-xdist](https://pytest-xdist.readthedocs.io/)), `php artisan test --parallel` or Pest/ParaTest. Limit the worker count to what memory allows (section 7.6).
- **Browser end-to-end tests** are usually the slowest part:
  - only run e2e for affected apps;
  - install only the browser you use (`playwright install chromium` or `chromium-headless-shell`), not all three;
  - use [sharding](https://playwright.dev/docs/test-sharding) across jobs only once you have several runners;
  - in CI use `retries: 1` or `2`, **and report flaky tests**, so they get fixed, not hidden ([Playwright CI guide](https://playwright.dev/docs/ci)).
- **No real sleeps or network calls** in tests: use fake timers and mocked HTTP. Each `sleep(2)` across 300 tests is 10 minutes.
- **Make missing test services fail in CI.** If a test file skips when `DATABASE_URL` is missing, make it **fail** when `CI=true` and the URL is missing. Otherwise a broken CI setup shows green while testing nothing. Also check, at least once, that those tests do skip cleanly on a machine without the services.

### 6.3 Generated code

He has a lot of it, and it is a classic source of slow and noisy CI.

1. **Mark it** in `.gitattributes` with `linguist-generated=true` ([docs](https://docs.github.com/en/repositories/working-with-files/managing-files/customizing-how-changed-files-appear-on-github)). PR diffs collapse it, so reviews focus on real code.
2. **Exclude it from linters, formatters, coverage and dead-code checks.** It isn't written by hand, so style findings in it are noise, and walking it costs time.
3. **Type-check it once, not repeatedly:** keep generated types in their own package or project, so incremental and cached builds reuse them (TypeScript project references, `skipLibCheck: true`).
4. **Decide: commit it, or generate it in CI.**
   - *Committed* (simpler, reviewable, works offline): CI checks it is **fresh**. It regenerates, then fails if `git status --porcelain -- <generated paths>` shows any difference, and the error message says which command to run. **Run this only when generator inputs change** (`CODEGEN_INPUTS` in A.3), or as a cached task whose inputs are the generator's inputs.
   - *Not committed* (smaller diffs, no drift possible): generation is a cached task that others depend on. Never regenerate it uncached on every run.
   Recommend one of these per generator, and explain why.
5. **Agent-generated code is still code:** it goes through the same checks, no exemptions.

### 6.4 Docker image builds

If CI builds the app's image:

- don't build it on every PR unless a Dockerfile or the app changed;
- use BuildKit cache (`cache-from` / `cache-to`: `type=gha` on hosted runners, the local builder cache on self-hosted ones);
- put the dependency install before copying the source (layer order);
- add a `.dockerignore`.

### 6.5 Shift left: check before pushing

- One local command runs what CI runs: `.github/scripts/ci-check.sh affected` (A.4). With `CI_BASE=$(git merge-base origin/main HEAD)` it checks what the branch changed.
- A fast pre-commit hook for format and lint of staged files only (e.g. `lefthook`, `husky` + `lint-staged`, or the `pre-commit` framework). Keep it under about 5 seconds, or he will skip it.
- If an agent writes code for him, its instructions should include running the local check before pushing, and batching commits instead of pushing every small change.

## 7. Phase 5: Self-hosted runners on OVHcloud VPS

### 7.1 Decide with numbers

| | GitHub-hosted | Self-hosted VPS |
| --- | --- | --- |
| Start state | Empty every time: reinstall tools, deps, browsers, images | Warm: tools, images, browsers, package stores stay |
| Cost | Per minute for private repos beyond the plan's included minutes | Fixed monthly per VPS |
| Size | 2 to 4 vCPU standard; larger runners cost more | You choose. On OVH, 4 to 8 vCPU / 8 to 16 GB is cheap |
| Maintenance | None | Scripts + automatic updates. Rebuild in about 30 minutes |
| Security | Isolated VM per job | **PR code runs on your machine**: private repos only, no secrets on it |
| Queue | Usually instant | Bounded by the number of runners |

**Self-hosted makes sense when** the audit shows a big share of time in setup and install, hosted minutes cost money, or jobs need more memory than hosted runners have. **It does not make sense for public repositories:** anyone can open a PR, and a fork's code would run on the machine ([GitHub's warning](https://docs.github.com/en/actions/hosting-your-own-runners/managing-self-hosted-runners/about-self-hosted-runners#self-hosted-runner-security)).

Check GitHub's current [Actions billing](https://docs.github.com/en/billing/managing-billing-for-your-products/managing-billing-for-github-actions/about-billing-for-github-actions) page for both hosted and self-hosted minutes, since pricing changed in 2026. Check [OVHcloud's VPS range](https://www.ovhcloud.com/fr/vps/) for current specs and prices: a 4 vCPU / 8 GB model costs a few euros to around fifteen euros a month. Put the comparison in the audit report, and let him decide.

### 7.2 Fleet design ("several CI services")

| Pool | Label | Where | Runs | Why |
| --- | --- | --- | --- | --- |
| **CI** | `ci` (+ each machine's own name, e.g. `ci-2`) | `ci-1` … `ci-N`, **one runner per VPS, one job at a time** | The `CI` job | One job per machine makes memory predictable and ports (5432…) conflict-free, and one bad job can't slow another |
| **Light** (optional) | `ci-light` | A second, small runner on each VPS | Jobs of seconds: labelling, status checks, bots | They would otherwise wait behind a 20-minute CI job |
| **Deploy** | GitHub-hosted + a GitHub **environment** | GitHub | Deployments, anything with secrets | Runners that run PR code must hold no secrets (P11) |
| **Heavy/e2e** (later, optional) | `ci-e2e` | A bigger VPS | Browser tests in a parallel job | Only once the audit shows e2e dominates |

**How many CI runners:** start with **2** (redundancy, and one can reboot for updates while the other works). Then size from the audit: `runners ≈ ceil(peak pushes per hour × job minutes / 60) + 1`. Add one when the p90 queue time goes above about a minute. Adding a runner is one script run, with no workflow change, because all CI runners share the label.

**Why several small VPS rather than one big one:** independent failure (one dies, CI continues), staggered reboots, no port or memory contention between jobs, and linear scaling. A big machine shares caches better, but a shared remote cache (7.8) gives that back.

### 7.3 Security model (explain this to him)

- The repository must be **private**. In Settings → Actions → General, keep "Run workflows from fork pull requests" **off**.
- Register runners **on the repository** (or in an organisation runner group restricted to that repo), never available to all repos.
- **No secrets on CI runners, and none in the CI job.** Deployments run on GitHub-hosted runners, in a GitHub [environment](https://docs.github.com/en/actions/managing-workflow-runs-and-deployments/managing-deployments/managing-environments-for-deployment) restricted to `main`, with its secrets there.
- **Never** use `pull_request_target` or `workflow_run` to check out and run PR code ([the "pwn request" pattern](https://securitylab.github.com/resources/github-actions-preventing-pwn-requests/)).
- **Network isolation:** SSH reachable only through a private network (VPN). The runner itself must not be able to reach his other devices, so a compromised dependency can't pivot to his laptop or servers.
- **Docker bypasses `ufw`**: published container ports are reachable from the internet even with `ufw deny`. The setup adds two locks (7.5).
- **The runner user has passwordless sudo and Docker** (GitHub-hosted runners do too, and steps like `playwright install --with-deps` need it). Membership in the `docker` group is worth root anyway. That is acceptable *only because* the machine holds nothing worth stealing.
- **Not `--ephemeral`:** ephemeral runners need a long-lived GitHub credential on the VPS to re-register after each job, which is worse. Instead, a job-completed hook wipes containers, leftover processes and the workspace after every job (7.5).

### 7.4 Where the infrastructure lives

Create a **separate private repository**, e.g. `ci-infra` (layout in Appendix B). **Why separate:** its README lists IP addresses, it changes on a different rhythm, and changes to it shouldn't trigger the app's CI. Rules for that repo:

- no secret ever (tokens and keys are read from local files at run time, passed on stdin, never on a command line);
- every machine can be rebuilt from it;
- `.gitattributes` forces LF line endings (a script with CRLF fails on Linux with `bad interpreter`: this bites Windows users with `core.autocrlf`);
- its own small CI runs `shellcheck` on GitHub-hosted runners (B.7).

### 7.5 What the setup does on each machine (and why)

All of this is in `setup.sh` (Appendix B.2). It runs on the VPS as root, with sub-steps, and every step is idempotent. `provision.sh` (B.3) runs on his computer and copies the folder over by SSH. `survey.sh` (B.4) only reads, to check that a fresh machine looks fresh.

| Area | What | Why |
| --- | --- | --- |
| Hostname | Set to `ci-N`, and cloud-init told to keep it | OVH's cloud-init otherwise puts its own name back at reboot |
| Packages | Full upgrade, Docker **from Ubuntu's archive**, jq, git, build tools, shellcheck | Ubuntu's Docker gets security updates through `unattended-upgrades` with no extra config |
| Swap | 4 GiB swap file | A memory peak goes to swap (slow) instead of the OOM killer (job dies). GitHub's hosted runners have swap too |
| SSH | Keys only; `authorized_keys` = exactly the keys in `keys/`; no root login; drop-in named `00-…` | sshd keeps the **first** value it reads, and OVH's `50-cloud-init.conf` enables passwords |
| Firewall | `ufw` deny inbound; SSH allowed only on the VPN interface once the VPN works | The public internet sees no open port |
| Docker lock 1 | `daemon.json` `"ip": "127.0.0.1"` | A port published without an address stays on loopback |
| Docker lock 2 | A `DOCKER-USER` iptables chain that drops traffic to containers unless it comes from Docker's own bridges, re-applied at every Docker start | Even `-p 0.0.0.0:5432` stays off the internet. Test databases accept connections without a password |
| Updates | `unattended-upgrades` with automatic reboot at **02:00 + N UTC** (ci-1 at 03:00, ci-2 at 04:00…), plus `DPkg::Lock::Timeout` | Kernel fixes apply, never two runners down at once, and a job that runs `apt-get` waits for the lock instead of failing |
| Runner | Pinned version **with SHA-256 check**, then it updates itself; systemd service; labels `ci,ci-N` | Reproducible install from a verified file. The per-machine label lets you target one machine (capacity test) |
| Memory limits | systemd `MemoryHigh` / `MemoryMax` on the runner's unit, `OOMPolicy=continue` | A runaway job is slowed, then has one process killed, while `sshd`, `dockerd` and the VPN keep their memory. That job fails, and the runner continues (the default policy would stop the whole service) |
| Restart | `Restart=always`, `RestartSec=15`, and before each start: kill all processes of the runner user, run the cleanup hook | The runner sometimes exits with code 0. A runner that died mid-job leaves nothing behind |
| Job hook | After each job: remove all containers (except the machine's own cache server), kill leftover processes working in `_work`, delete the workspace. Never fails | Stands in for `--ephemeral`. The runner's own cleanup misses processes that dropped its tracking variable (e.g. a dev server started by a cancelled test). The runner refuses hooks not ending in `.sh`, and a failing hook fails the job |
| Kept between jobs | Tool cache (`_work/_tool`), Docker images, package stores, browser cache | This is the whole point of a warm runner (P9) |
| Hourly cleanup | Prune old stopped containers, old builder cache, journals, runner logs. **Over 70 % disk with no job running:** prune images and all caches | The disk never fills, and everything removed can be downloaded again |
| `.env` of the runner | `TASK_CONCURRENCY`, the hook, optional cache settings | Every job inherits them, with no change to the workflow. GitHub-hosted runs aren't affected |

### 7.6 Sizing: the capacity test

**Never guess the parallelism. Measure it.** The usual failure: the task runner defaults to one task per CPU, a few production builds (about 2 GB each) and test workers run together, the machine swaps hard or kills a process, and a test times out "randomly".

The workflow in Appendix A.2 accepts a manual run with inputs `runner` (e.g. `ci-1`), `measure: true` and `concurrency`. With `measure`, `mem-sampler.sh` (A.6) logs memory every second and writes the peaks to the job summary: lowest available memory, peak swap, the job's own memory, the containers' memory, and OOM kills.

Procedure, per VPS size:

```sh
gh workflow run ci.yml -f runner=ci-1 -f measure=true -f concurrency=4
gh workflow run ci.yml -f runner=ci-1 -f measure=true -f concurrency=3
gh workflow run ci.yml -f runner=ci-1 -f measure=true -f concurrency=2
```

Pick the **highest concurrency that never swaps and keeps about 1.5 GB available at the peak.** Record the table in the infra README, then set `TASK_CONCURRENCY` in `ci.env` and re-run `provision.sh ci-N runner` on each machine.

A real example, on a 4 vCPU / 8 GB VPS running a full check of about 120 tasks:

| Concurrency | Duration | Result |
| --- | --- | --- |
| 4 | 17 min | Ran out of memory on some runs; one browser test timed out |
| 3 | 15 min 18 s | Passed, but swapped 2 GB for 2 minutes (risky on a slow disk) |
| 2 | 16 min 18 s | Passed, no swap, 1.6 GB free at the peak. **Chosen** |

Lesson: one minute slower, but never flaky. Swap and memory limits are a safety net, not capacity. Repeat the test when the codebase grows a lot, or when monitoring shows a runner short of memory.

### 7.7 Rollout and rollback

1. Provision the runners (B.1 steps). They register and sit idle: nothing uses them yet.
2. The workflow selects runners from a **repository variable**:
   ```yaml
   runs-on: ${{ fromJSON(vars.CI_RUNS_ON || '"ubuntu-24.04"') }}
   ```
3. Go live:
   ```sh
   gh variable set CI_RUNS_ON --repo OWNER/REPO --body '["self-hosted","ci"]'
   ```
4. Go back (instant, no commit):
   ```sh
   gh variable delete CI_RUNS_ON --repo OWNER/REPO
   ```
   A run that already started keeps its runner. Cancel and rerun anything stuck waiting for a self-hosted runner.

**Why a variable:** switching or rolling back takes one command, needs no PR, and a broken runner fleet never blocks his work.

**Self-hosted runners are not the hosted image.** They don't have its pre-installed tools. The workflow must install its own toolchain through `setup-*` actions (which cache it in `_work/_tool` on the runner). Never assume something is "just there".

**Drain before restarting a runner.** To change a runner without failing a job, remove its `ci` label through the API (GitHub then stops sending it jobs), wait until it is idle, change it, and put the label back. `provision.sh` does this automatically (`drained` in B.3).

### 7.8 A shared task cache on OVHcloud Object Storage (optional, after 7.7)

With several runners, each machine's local cache only helps the jobs that land on it. A **shared remote cache** makes a task that passed anywhere (any runner, any PR, `main`) replay everywhere.

- **Storage:** an OVHcloud Public Cloud **Object Storage** bucket ([product page](https://www.ovhcloud.com/fr/public-cloud/object-storage/), S3-compatible, endpoint `https://s3.<region>.io.cloud.ovh.net`). Pick the region closest to the VPS. Create an S3 user **that can reach this bucket only**, and a **lifecycle rule** that deletes objects after 14 days:
  ```sh
  aws s3api put-bucket-lifecycle-configuration --endpoint-url https://s3.<region>.io.cloud.ovh.net \
    --bucket <bucket> --lifecycle-configuration \
    '{"Rules":[{"ID":"expire","Status":"Enabled","Filter":{"Prefix":""},"Expiration":{"Days":14}}]}'
  ```
  The cost is cents a month for a project this size.
- **Server:** for Turborepo, a self-hosted remote cache server such as [`turborepo-remote-cache`](https://github.com/ducktors/turborepo-remote-cache) (S3 backend), as a Docker container **on each runner, listening on `127.0.0.1` only**, pinned by digest (`setup.sh task-cache`, B.2). The runner's `.env` points jobs at it (`TURBO_API`, `TURBO_TEAM`, `TURBO_TOKEN`). For Nx, see [Nx's self-hosted cache options](https://nx.dev/recipes/running-tasks/self-hosted-caching). If the server is down, the tool just runs the tasks.
- **Trust, said plainly:** a job runs PR code as root, so it can read the bucket key and write fake cache entries that a later run would replay as "passed". On a private, single-developer repo with no outside contributors, that's the same trust he already gives his own PRs, and the key reaches nothing but this bucket. **On any repo with outside contributors, make PR jobs read-only on the cache.**
- **Workflow:** skip `actions/cache` for task results when a shared cache is configured (the workflow in A.2 detects it), and set up the cache in a separate PR from the switch to self-hosted runners.

### 7.9 Operations

- **Status:** `./provision.sh ci-N status` prints SSH settings, firewall, Docker rules, units, memory limits, swap, listening ports and disk. Runner state: `gh api repos/OWNER/REPO/actions/runners --jq '.runners[] | [.name,.status,.busy] | @tsv'`.
- **Monitoring** (suggest, then let him choose): a dead-man's switch (e.g. a systemd timer that pings a free uptime-check service while the runner unit is active), or a daily scheduled workflow on a GitHub-hosted runner that lists runners and opens an issue if one is offline. That needs a token with runner read rights, kept in a GitHub secret.
- **Rebuild a machine:** stop its runner when idle, reinstall the OS from the OVH control panel, remove it from the VPN admin console, forget its old SSH host keys (`ssh-keygen -R <ip>`), then run the same steps as for a new machine. `--replace` takes over the runner's name on GitHub.
- **Runner version:** `setup.sh` pins it for the first install, and the runner then updates itself. If a much later install refuses the pinned version, update `RUNNER_VERSION` and `RUNNER_SHA256` from the [releases page](https://github.com/actions/runner/releases).
- **Images:** pin test service images by tag **and digest** in one file (`ci/images.env`). Image publishers rebuild tags in place. Update the digest on purpose, in its own PR, which reruns every test.

## 8. Phase 5b: The private network (VPN) for admin access

**Goal:** public SSH closed, admin access only through a private network, and runners that can reach none of his devices.

Simplest for a non-professional: a mesh VPN such as Tailscale (free personal plan; check the limits for a group), or NetBird. Plain [WireGuard](https://www.wireguard.com/quickstart/) works too, with more manual key handling. `setup.sh vpn` (B.2) uses Tailscale:

- The machines join with a **tag** (`tag:ci`), using an **auth key that expires in 1 day** and is not reusable (unless you add several machines at once). The key is read from a file, not typed on a command line.
- The tailnet policy **must be replaced**: a new tailnet allows all-to-all by default. Policy in B.6: admins reach the runners, and **`tag:ci` reaches nothing**. Its `tests` section makes the admin console refuse a policy that breaks this.
- Join with `--netfilter-mode=off`, so `ufw` stays the only firewall. Otherwise the VPN's own rules accept all tailnet traffic ahead of `ufw`, and on a restart they go above `DOCKER-USER`.
- **Close public SSH only after** SSH through the VPN works, then reboot once to prove the machine comes back reachable. If the VPN ever fails, use the OVH control panel's **rescue mode**.
- Check the isolation from a runner. This must print `blocked`:
  ```sh
  timeout 6 bash -c '</dev/tcp/<one-of-his-device-vpn-ips>/22' && echo REACHABLE || echo blocked
  ```

If he doesn't want a VPN, the fallback is public SSH with keys only (which `base` already enforces). Explain that it's acceptable, but noisier and one config mistake away from exposure.

## 9. Phase 6: Merging rules

- Protect `main` with a **ruleset** ([docs](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/about-rulesets)): changes through PRs, no force-push, no deletion, and the required check `CI` **from GitHub Actions** (`integration_id` 15368, so no other app or person can fake it). On private repos this needs a paid plan (Pro/Team). Check his.
  ```sh
  gh api --method POST repos/OWNER/REPO/rulesets --input - <<'EOF'
  {
    "name": "main",
    "target": "branch",
    "enforcement": "active",
    "conditions": { "ref_name": { "include": ["~DEFAULT_BRANCH"], "exclude": [] } },
    "rules": [
      { "type": "deletion" },
      { "type": "non_fast_forward" },
      { "type": "pull_request", "parameters": {
          "required_approving_review_count": 0, "dismiss_stale_reviews_on_push": false,
          "require_code_owner_review": false, "require_last_push_approval": false,
          "required_review_thread_resolution": false } },
      { "type": "required_status_checks", "parameters": {
          "strict_required_status_checks_policy": false,
          "required_status_checks": [ { "context": "CI", "integration_id": 15368 } ] } }
    ]
  }
  EOF
  ```
- **"Require branches to be up to date" (strict): recommend off** for a solo developer. With it on, every merge forces every other open PR to update and rerun CI. With it off, the full run on `main` after each merge catches the rare "two PRs that break together" case, and a quick follow-up fixes it.
- **Merge queue** ([docs](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue)): the proper fix for that case, if his plan offers it for this repo. It needs `merge_group:` in the workflow's triggers (mode `full` in the scope script).
- **Optional advanced idea:** a small "Main" status job that holds every merge while `main`'s latest CI run is red, so auto-merge can't pile changes onto a broken `main`. Suggest it only if he uses auto-merge heavily.
- Settings → General: enable "Automatically delete head branches".

## 13. Pitfalls checklist (real failures seen in practice)

- A test that **silently skips** when its service URL is missing makes CI green while testing nothing.
- **Docker publishes ports around `ufw`.** Use both locks of 7.5.
- **Leftover processes** from cancelled jobs (dev servers) keep ports and memory, and fail the next job. The hook kills by working directory.
- The runner service **exiting with 0**, then staying down, needs `Restart=always`.
- **systemd's default OOM policy stops the whole runner service.** Set `OOMPolicy=continue`.
- **cloud-init restores the hostname** on OVH. Set `preserve_hostname`.
- **sshd's first value wins.** A drop-in named `50-…` comes after OVH's own and loses, so use `00-…`.
- **`apt` lock conflicts** between automatic updates and jobs installing packages. Set `DPkg::Lock::Timeout`.
- **All runners rebooting at the same hour** takes CI down. Stagger the reboots.
- **Tiny jobs waiting behind long ones** on the same runner. Give them a light runner.
- **GitHub's cache isn't shared from PRs to `main`**, and is evicted by big entries. Use split restore/save, restore-keys, saving on failure, and pruning.
- **A skipped required job counts as passed; a workflow that never runs blocks forever.**
- **Hidden inputs** (tests reading files outside their module) need the global list and a check to keep it current.
- **Docs-only fast paths** must not let through files that change tool behaviour (lockfiles, workspace or tool config placed in `docs/`).
- **Image tags get rebuilt in place.** Pin by digest.
- **Some images ship only `linux/amd64`.** Choose x86-64 VPS, or check that every image you need ships `arm64` too.
- **Registration tokens last 1 hour and are single-use.** `provision.sh` fetches a fresh one each time.
- **CRLF line endings** break shell scripts copied from Windows. Use `.gitattributes`.
- **Too much parallelism** causes swap, timeouts, and "flaky" tests that are really memory pressure. Run the capacity test.

## A.1 `tools/ci_audit.py`

```python
#!/usr/bin/env python3
"""Where does CI time go? Reads the latest completed runs of a workflow through the GitHub CLI and
prints, per event, job and step, median and p90 durations, how long jobs waited for a runner, and
the daily load. Changes nothing.

    python3 tools/ci_audit.py OWNER/REPO [--workflow ci.yml] [--runs 50] [--json out.json]

Needs `gh` logged in with read access to the repository's Actions. Standard library only.
"""
import argparse
import json
import statistics
import subprocess
from collections import Counter, defaultdict
from datetime import datetime


def gh(path):
    out = subprocess.run(["gh", "api", path], check=True, capture_output=True, text=True).stdout
    return json.loads(out)


def ts(value):
    return datetime.fromisoformat(value.replace("Z", "+00:00")) if value else None


def seconds(start, end):
    a, b = ts(start), ts(end)
    return (b - a).total_seconds() if a and b else None


def p90(values):
    s = sorted(values)
    return s[min(len(s) - 1, round(0.9 * (len(s) - 1)))]


def fmt(sec):
    m, s = divmod(int(round(sec)), 60)
    return f"{m}m{s:02d}s"


def fetch_runs(repo, workflow, count):
    runs, page = [], 1
    while len(runs) < count:
        data = gh(f"repos/{repo}/actions/workflows/{workflow}/runs?status=completed&per_page=100&page={page}")
        batch = data.get("workflow_runs", [])
        if not batch:
            break
        runs.extend(batch)
        page += 1
    return runs[:count]


def main():
    parser = argparse.ArgumentParser(description=__doc__, formatter_class=argparse.RawDescriptionHelpFormatter)
    parser.add_argument("repo")
    parser.add_argument("--workflow", default="ci.yml")
    parser.add_argument("--runs", type=int, default=50)
    parser.add_argument("--json", help="also write the raw rows to this file")
    args = parser.parse_args()

    runs = fetch_runs(args.repo, args.workflow, args.runs)
    if not runs:
        raise SystemExit("No completed runs found.")

    run_rows, job_rows, step_rows = [], [], []
    for run in runs:
        wall = seconds(run.get("run_started_at"), run.get("updated_at"))
        run_rows.append({"id": run["id"], "event": run["event"], "conclusion": run["conclusion"],
                         "day": (run.get("run_started_at") or "")[:10], "wall": wall})
        jobs = gh(f"repos/{args.repo}/actions/runs/{run['id']}/jobs?per_page=100").get("jobs", [])
        for job in jobs:
            duration = seconds(job.get("started_at"), job.get("completed_at"))
            if duration is None or job.get("conclusion") == "skipped":
                continue
            job_rows.append({"run": run["id"], "event": run["event"], "day": run_rows[-1]["day"],
                             "job": job["name"], "runner": job.get("runner_name") or "?",
                             "queue": seconds(job.get("created_at"), job.get("started_at")) or 0,
                             "duration": duration})
            for step in job.get("steps") or []:
                s = seconds(step.get("started_at"), step.get("completed_at"))
                if s is None or step.get("conclusion") == "skipped":
                    continue
                step_rows.append({"event": run["event"], "job": job["name"], "step": step["name"],
                                  "seconds": s, "share": s / duration if duration else 0})

    days = sorted({r["day"] for r in run_rows if r["day"]})
    print(f"Runs read: {len(run_rows)} of {args.workflow}, {days[0]} to {days[-1]}")
    print("Events:      " + ", ".join(f"{k} {v}" for k, v in Counter(r["event"] for r in run_rows).items()))
    print("Conclusions: " + ", ".join(f"{k} {v}" for k, v in Counter(r["conclusion"] for r in run_rows).items()))

    print("\n== Wall time per run ==")
    print(f"{'event':<20}{'runs':>6}{'median':>10}{'p90':>10}")
    by_event = defaultdict(list)
    for r in run_rows:
        if r["wall"] is not None and r["conclusion"] != "cancelled":
            by_event[r["event"]].append(r["wall"])
    for event, values in sorted(by_event.items()):
        print(f"{event:<20}{len(values):>6}{fmt(statistics.median(values)):>10}{fmt(p90(values)):>10}")

    print("\n== Jobs: waiting for a runner, then running ==")
    print(f"{'event / job':<40}{'n':>5}{'queue med':>11}{'queue p90':>11}{'run med':>10}{'run p90':>10}")
    groups = defaultdict(list)
    for j in job_rows:
        groups[(j["event"], j["job"])].append(j)
    for (event, job), rows in sorted(groups.items()):
        q = [r["queue"] for r in rows]
        d = [r["duration"] for r in rows]
        label = f"{event} / {job}"[:39]
        print(f"{label:<40}{len(rows):>5}{fmt(statistics.median(q)):>11}{fmt(p90(q)):>11}"
              f"{fmt(statistics.median(d)):>10}{fmt(p90(d)):>10}")

    print("\n== Slowest steps (by median), with their median share of the job ==")
    print(f"{'job / step':<60}{'n':>5}{'median':>10}{'p90':>10}{'share':>8}")
    steps = defaultdict(list)
    for s in step_rows:
        steps[(s["job"], s["step"])].append(s)
    ranked = sorted(steps.items(), key=lambda kv: -statistics.median(x["seconds"] for x in kv[1]))
    for (job, step), rows in ranked[:20]:
        sec = [r["seconds"] for r in rows]
        share = statistics.median(r["share"] for r in rows)
        label = f"{job} / {step}"[:59]
        print(f"{label:<60}{len(rows):>5}{fmt(statistics.median(sec)):>10}{fmt(p90(sec)):>10}{share:>7.0%}")

    print("\n== Load ==")
    per_day = defaultdict(lambda: [0, 0.0])
    for r in run_rows:
        per_day[r["day"]][0] += 1
    for j in job_rows:
        per_day[j["day"]][1] += j["duration"] / 60
    counts = [v[0] for v in per_day.values()]
    minutes = [v[1] for v in per_day.values()]
    print(f"Runs per active day: mean {statistics.mean(counts):.1f}, max {max(counts)}")
    print(f"Job minutes per active day: mean {statistics.mean(minutes):.0f}, max {max(minutes):.0f}")
    print("Runners used: " + ", ".join(f"{k} {v}" for k, v in Counter(j["runner"] for j in job_rows).most_common(10)))

    if args.json:
        with open(args.json, "w", encoding="utf-8") as f:
            json.dump({"runs": run_rows, "jobs": job_rows, "steps": step_rows}, f, indent=1)
        print(f"\nRaw rows written to {args.json}")


if __name__ == "__main__":
    main()
```

## A.2 `.github/workflows/ci.yml` (example: Node monorepo with a task runner and Postgres)

The structure is stack-agnostic. Only the "toolchain" and "install" steps change per stack. Everything project-specific is in `.github/scripts/ci-check.sh`.

```yaml
name: CI

# Checks every pull request and every push to main. How it works: docs/ci.md.
# - The Scope step picks a mode from the changed files: full, affected or docs (ci-scope.sh).
# - The job always runs and has no job-level `if:`: it is the required check `CI`, and a skipped
#   job would count as passed.
# - No secret is used here. Deployment runs elsewhere, on main only, in a GitHub environment.
on:
  pull_request:
  push:
    branches: [main]
  # merge_group:            # uncomment if the merge queue is turned on
  workflow_dispatch:         # manual full run; also the capacity test (docs/ci.md)
    inputs:
      runner:
        description: "Run on this one self-hosted runner (its own label, e.g. ci-2). Empty: the usual runners."
        required: false
        default: ""
      measure:
        description: "Log memory every second and report the peaks (capacity test)"
        type: boolean
        default: false
      concurrency:
        description: "Tasks at once for this run (empty: the runner's own TASK_CONCURRENCY)"
        required: false
        default: ""

permissions:
  contents: read

# A newer push to a pull request cancels its running checks. On main, a started run finishes and a
# newer push replaces a waiting one. Manual runs never cancel anything.
concurrency:
  group: ci-${{ github.event_name == 'workflow_dispatch' && github.run_id || github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

jobs:
  ci:
    name: CI   # the check the main ruleset requires: keep the name
    # GitHub-hosted by default. The repository variable CI_RUNS_ON (a JSON list of labels, e.g.
    # '["self-hosted","ci"]') moves the job to the self-hosted runners; deleting it moves it back.
    runs-on: ${{ fromJSON(inputs.runner && format('["self-hosted","{0}"]', inputs.runner) || vars.CI_RUNS_ON || '"ubuntu-24.04"') }}
    timeout-minutes: 30
    env:
      # One container per run attempt, so a rerun never meets the previous one's.
      CI_DB_CONTAINER: ci-db-${{ github.run_id }}-${{ github.run_attempt }}
      # A throwaway database that accepts connections from this machine only, without a password.
      TEST_DATABASE_URL: postgres://app@127.0.0.1:5432/app_test
    steps:
      - uses: actions/checkout@<sha> # <version>
        with:
          fetch-depth: 2              # HEAD^1 is the base branch tip on a pull request
          persist-credentials: false

      - name: Scope
        id: scope
        env:
          EVENT: ${{ github.event_name }}
        run: bash .github/scripts/ci-scope.sh

      - name: Start the memory sampler
        if: inputs.measure
        run: bash .github/scripts/mem-sampler.sh start

      - name: Set the concurrency of this run
        if: inputs.concurrency != ''
        env:
          WANT: ${{ inputs.concurrency }}
        run: |
          # Through env, never interpolated into the script: an input is untrusted text.
          [[ $WANT =~ ^[1-9][0-9]?$ ]] || { echo "::error::concurrency must be a number"; exit 1; }
          echo "TASK_CONCURRENCY=$WANT" >>"$GITHUB_ENV"

      # Started before the install: the image pull and the boot overlap with it.
      - name: Start the test services
        if: steps.scope.outputs.mode != 'docs'
        run: bash .github/scripts/test-services.sh start

      # --- Toolchain: Node + pnpm example. Versions come from files in the repo. ---------------
      # On self-hosted runners the package store stays on the machine, so GitHub's cache is skipped.
      - uses: pnpm/action-setup@<sha> # <version>
      - uses: actions/setup-node@<sha> # <version>
        with:
          node-version-file: .nvmrc
          cache: ${{ runner.environment == 'github-hosted' && steps.scope.outputs.mode != 'docs' && 'pnpm' || '' }}
      # Python: actions/setup-python or astral-sh/setup-uv. PHP: shivammathur/setup-php.

      - name: Install
        run: pnpm install --frozen-lockfile

      # Browsers for end-to-end tests: kept between jobs on self-hosted runners.
      # - name: Install the browsers
      #   if: steps.scope.outputs.mode != 'docs'
      #   run: pnpm exec playwright install --with-deps chromium

      # --- Task results cache --------------------------------------------------------------------
      # A shared cache server (self-hosted runners, docs/ci.md) replaces GitHub's cache.
      - name: Task cache
        id: task-cache
        run: |
          if [ -n "${TURBO_API:-}" ]; then
            echo "Shared task cache at $TURBO_API."
            echo "github=false" >>"$GITHUB_OUTPUT"
          else
            echo "No shared task cache: GitHub's cache keeps the task results."
            echo "github=true" >>"$GITHUB_OUTPUT"
            echo "TURBO_CACHE_DIR=.cache/tasks" >>"$GITHUB_ENV"
          fi

      - name: Restore the task cache
        id: restore
        if: steps.task-cache.outputs.github == 'true' && steps.scope.outputs.mode != 'docs'
        uses: actions/cache/restore@<sha> # <version>
        with:
          path: .cache/tasks
          key: tasks-${{ runner.os }}-${{ github.sha }}
          restore-keys: tasks-${{ runner.os }}-   # this PR's latest, or else main's

      - name: Wait for the test services
        if: steps.scope.outputs.mode != 'docs'
        run: bash .github/scripts/test-services.sh wait

      - name: Check
        id: check
        env:
          MODE: ${{ steps.scope.outputs.mode }}
          CODEGEN: ${{ steps.scope.outputs.codegen }}
        run: bash .github/scripts/ci-check.sh "$MODE"

      - name: Memory report
        if: always() && inputs.measure
        run: bash .github/scripts/mem-sampler.sh report

      - uses: actions/upload-artifact@<sha> # <version>
        if: always() && inputs.measure
        with:
          name: memory-${{ github.run_id }}
          path: ${{ runner.temp }}/mem.csv

      # Saved even when a check failed, so the tasks that passed don't run again.
      - name: Prune the task cache
        if: ${{ !cancelled() && steps.task-cache.outputs.github == 'true' && steps.check.outcome != 'skipped' && steps.scope.outputs.mode != 'docs' }}
        run: find .cache/tasks -type f -mtime +14 -delete 2>/dev/null || true
      - name: Save the task cache
        if: ${{ !cancelled() && steps.task-cache.outputs.github == 'true' && steps.check.outcome != 'skipped' && steps.scope.outputs.mode != 'docs' && steps.restore.outputs.cache-hit != 'true' }}
        uses: actions/cache/save@<sha> # <version>
        with:
          path: .cache/tasks
          key: tasks-${{ runner.os }}-${{ github.sha }}

      - name: Stop the test services
        if: always() && steps.scope.outputs.mode != 'docs'
        run: bash .github/scripts/test-services.sh stop
```

Notes for you (the agent):

- `runner.environment` is `github-hosted` or `self-hosted`. The task-cache decision is a step because the runner's own environment (its `.env`) is visible to shell steps, not to `${{ }}` expressions.
- In `docs` mode, install only what the docs checks need, if the package manager allows it (e.g. `pnpm install --filter=<root>`). And don't save a dependency cache from a partial install, or you poison the cache key.
- Service containers (`services:`) also work, but they start before every step, so they block instead of overlapping with the install, and they publish on all interfaces. That's why the script starts them itself.

## A.3 `.github/scripts/ci-scope.sh`

```bash
#!/usr/bin/env bash
# Decides how much a CI run checks, from the files the change touches. Needs bash 4.4 or later.
#
#   ci-scope.sh                    in CI. EVENT is github.event_name. On a pull request, compares
#                                  HEAD^1 (the base branch tip) with HEAD (the merge commit that
#                                  actions/checkout makes): it needs fetch-depth: 2.
#   ci-scope.sh --base <ref>       locally: compares the merge base of <ref> and HEAD with HEAD
#   ci-scope.sh --files <file>     in tests: the changed paths, one per line, from <file>
#
# Prints the mode and why. With GITHUB_OUTPUT set, writes mode=full|affected|docs, reason=...,
# codegen=true|false and modules=<JSON list> there, and the reason to the job summary.
#
# When in doubt, run more: a wrong "docs" or "affected" lets a broken change merge, a wrong "full"
# only costs minutes.
set -euo pipefail

# --------------------------------------------------------------------------------------------------
# Edit these lists for the project. Each entry is an extended regex matched against the WHOLE path
# (grep -xE). Keep a comment on each entry that says which checks read the file.
# --------------------------------------------------------------------------------------------------

# A change to one of these checks everything: files every check depends on but no module owns, and
# files that tests read from outside their own module. Matched ignoring case: on a case-insensitive
# disk, Package-Lock.json is package-lock.json.
FULL_RUN=(
  '\.github/workflows/ci\.yml'                        # the pipeline itself
  '\.github/scripts/.+'                               # the scripts it runs, this one included
  'ci/images\.env'                                    # the test services' images
  '\.nvmrc|\.node-version|\.tool-versions|\.python-version|\.php-version'  # toolchain versions
  # Lockfiles and package-manager settings, anywhere: run in a folder that holds one, the package
  # manager may read it instead of the root's, even under docs/.
  '(.+/)?(package-lock\.json|pnpm-lock[^/]*\.yaml|yarn\.lock|bun\.lockb?|composer\.lock|poetry\.lock|uv\.lock|Pipfile\.lock|Gemfile\.lock)'
  '(.+/)?(pnpm-workspace\.yaml|\.npmrc|\.yarnrc\.yml|\.pnpmfile\.[^/]+)'
  'package\.json|composer\.json|pyproject\.toml'      # the root manifests
  'tsconfig(\.base)?\.json'                           # shared compiler settings
  'turbo\.json|nx\.json'                              # the task runner's own settings
  # '<path/a/test/reads>'                             # a file a test reads outside its module
)

# Files that need only the docs checks, when EVERY changed file is one, and none is on FULL_RUN
# (tested first).
DOCS_ONLY=(
  '.+\.md'
  'docs/.+'
  'LICENSE'
)

# Inputs of code generation: a change to one makes the check regenerate and compare (codegen=true).
CODEGEN_INPUTS=(
  # 'prisma/schema\.prisma'
  # 'api/openapi\.ya?ml'
)

# For a project without a workspace graph: one regex per module folder, whose first group is the
# module's name. A module that others import belongs in FULL_RUN instead.
MODULE_PATTERNS=(
  # 'modules/([^/]+)/.+'
)

# --------------------------------------------------------------------------------------------------

alternation() { local IFS='|'; [ $# -gt 0 ] && echo "($*)"; }
# matches_any <grep flags> <patterns...>: some changed path matches one of the patterns.
matches_any() {
  local flags=$1 pattern
  shift
  pattern=$(alternation "$@") || return 1
  grep -q"$flags"xE "$pattern" <<<"$changed"
}
# all_match <patterns...>: every changed path matches one of the patterns.
all_match() {
  local pattern
  pattern=$(alternation "$@") || return 1
  ! grep -vqxE "$pattern" <<<"$changed"
}

event=${EVENT:-${GITHUB_EVENT_NAME:-}}
changed=""
mode="" reason=""
case "${1:-}" in
  --files) changed=$(grep -v '^$' "${2:?--files needs a file}" || true); event=pull_request ;;
  --base)
    base=$(git merge-base "${2:?--base needs a ref}" HEAD)
    changed=$(git diff --name-only --no-renames "$base" HEAD)
    event=pull_request
    ;;
  "")
    if [ "$event" = pull_request ]; then
      if git rev-parse --verify --quiet 'HEAD^1' >/dev/null; then
        # --no-renames lists both paths of a moved file.
        changed=$(git diff --name-only --no-renames 'HEAD^1' HEAD)
      else
        mode=full
        reason="No base commit to compare with (the checkout needs fetch-depth: 2): everything."
      fi
    fi
    ;;
  *) echo "usage: ci-scope.sh [--files <file> | --base <ref>]" >&2; exit 2 ;;
esac

if [ -n "$mode" ]; then
  :
elif [ "$event" != pull_request ]; then
  mode=full
  reason="${event:-local} run: everything."
elif [ -z "$changed" ]; then
  # An empty change: let the task runner decide, which runs the repository checks.
  mode=affected
  reason="No file changed: the repository checks."
elif matches_any i "${FULL_RUN[@]}"; then
  mode=full
  reason="Changes a file every check depends on ($(grep -ixE "$(alternation "${FULL_RUN[@]}")" <<<"$changed" | head -n 3 | paste -sd, -)): everything."
elif all_match "${DOCS_ONLY[@]}"; then
  mode=docs
  reason="Documentation only: the docs and format checks."
else
  mode=affected
  reason="The modules this change touches, the modules that depend on them, and the repository checks."
fi

codegen=false
if [ "$mode" = full ] || { [ "$mode" = affected ] && matches_any "" "${CODEGEN_INPUTS[@]}"; }; then
  codegen=true
fi

modules=()
if [ "$mode" = affected ]; then
  for pattern in "${MODULE_PATTERNS[@]}"; do
    while IFS= read -r path; do
      if [[ $path =~ ^${pattern}$ ]]; then modules+=("${BASH_REMATCH[1]}"); fi
    done <<<"$changed"
  done
fi
if [ "${#modules[@]}" -gt 0 ]; then
  modules_json=$(printf '%s\n' "${modules[@]}" | sort -u | jq -R . | jq -sc .)
else
  modules_json='[]'
fi

echo "Scope: $mode. $reason"
if [ -n "${GITHUB_OUTPUT:-}" ]; then
  {
    echo "mode=$mode"
    echo "reason=$reason"
    echo "codegen=$codegen"
    echo "modules=$modules_json"
  } >>"$GITHUB_OUTPUT"
fi
if [ -n "${GITHUB_STEP_SUMMARY:-}" ]; then
  echo "**Scope: $mode.** $reason" >>"$GITHUB_STEP_SUMMARY"
fi
```

```bash
#!/usr/bin/env bash
# The throwaway servers the tests need, on 127.0.0.1 only:  test-services.sh start|wait|stop
# `start` returns at once, so the servers boot while dependencies install; `wait` blocks until they
# answer. Locally, set CI_DB_PORT to a free port and CI_DB_CONTAINER to any name.

image=$(sed -n 's/^POSTGRES_IMAGE=//p' "$images")
db=${CI_DB_CONTAINER:-ci-db-local}
port=${CI_DB_PORT:-5432}

case "${1:-}" in
  start)
    [ -n "$image" ] || { echo "no POSTGRES_IMAGE in $images" >&2; exit 1; }
    echo "Image: $image"
    # Data on tmpfs and durability off: a test database is thrown away, and this is much faster.
    # The health check goes through TCP: on first boot the image runs a socket-only server, then restarts.
    docker run --detach --name "$db" --publish "127.0.0.1:$port:5432" \
      --env POSTGRES_USER=app --env POSTGRES_DB=app_test --env POSTGRES_HOST_AUTH_METHOD=trust \
      --tmpfs /var/lib/postgresql \
      --health-cmd "pg_isready --host=127.0.0.1 --username=app --dbname=app_test" \
      --health-interval 1s --health-timeout 5s --health-retries 120 \
      "$image" -c fsync=off -c synchronous_commit=off -c full_page_writes=off >/dev/null
    ;;
  wait)
    state=""
    for _ in $(seq 120); do
      state=$(docker inspect --format '{{.State.Status}} {{.State.Health.Status}}' "$db")
      case "$state" in
        "running healthy") exit 0 ;;
        running*) sleep 1 ;;
        *) break ;;
      esac
    done
    echo "The database did not become healthy: $state"
    docker logs "$db"
    exit 1
    ;;
  stop) docker rm --force --volumes "$db" >/dev/null 2>&1 || true ;;
  *) echo "usage: test-services.sh start|wait|stop" >&2; exit 2 ;;
esac
```

## A.6 `.github/scripts/mem-sampler.sh` (capacity test)

```bash
#!/usr/bin/env bash
# Measures a CI job's memory for the capacity test:  mem-sampler.sh start | report
#   start   logs once a second, in the background, to $RUNNER_TEMP/mem.csv
#   report  writes the peaks to the job summary
# "job" is this job's cgroup (the runner's systemd unit on a self-hosted runner); "containers" are
# the Docker containers, which live in their own cgroups, outside the runner's memory limits.
set -euo pipefail
log=${RUNNER_TEMP:-/tmp}/mem.csv
cgroup=/sys/fs/cgroup$(cut -d: -f3 /proc/self/cgroup | head -n 1)
mib() { cat "$@" 2>/dev/null | awk '{s += $1} END {printf "%d", s / 1048576}'; }
oom_kills() { awk '$1 == "oom_kill" {print $2}' "$cgroup/memory.events" 2>/dev/null || echo 0; }

case "${1:-}" in
  start)
    echo "time,available_mib,swap_used_mib,job_mib,containers_mib" >"$log"
    oom_kills >"$log.oom-start"
    nohup bash "$0" loop >/dev/null 2>&1 &
    echo "Sampling memory every second into $log"
    ;;
  loop)
    while :; do
      read -r avail swap < <(awk '/^MemAvailable:/ {a=$2} /^SwapTotal:/ {t=$2} /^SwapFree:/ {f=$2}
        END {printf "%d %d\n", a/1024, (t-f)/1024}' /proc/meminfo)
      echo "$(date +%s),$avail,$swap,$(mib "$cgroup/memory.current"),$(mib /sys/fs/cgroup/system.slice/docker-*.scope/memory.current)" >>"$log"
      sleep 1
    done
    ;;
  report)
    total=$(awk '/^MemTotal:/ {printf "%d", $2/1024}' /proc/meminfo)
    kills=$(( $(oom_kills) - $(cat "$log.oom-start" 2>/dev/null || echo 0) ))
    {
      echo "### Memory (capacity test)"
      echo
      echo "Runner: ${RUNNER_NAME:-?}, $(nproc) CPUs, ${total} MiB RAM, TASK_CONCURRENCY=${TASK_CONCURRENCY:-default}"
      echo
      awk -F, -v kills="$kills" 'NR == 2 {min = $2} NR > 1 {
          if ($2 < min) min = $2; if ($3 > swap) swap = $3; if ($4 > job) job = $4; if ($5 > ct) ct = $5; n++ }
        END {
          print "| Measure | Value |"; print "| --- | --- |"
          printf "| Lowest available memory | %d MiB |\n", min
          printf "| Peak swap in use | %d MiB |\n", swap
          printf "| Peak job memory | %d MiB |\n", job
          printf "| Peak containers memory | %d MiB |\n", ct
          printf "| Processes killed for memory | %d |\n", kills
          printf "| Samples | %d s |\n", n }' "$log"
    } >>"${GITHUB_STEP_SUMMARY:-/dev/stdout}"
    ;;
  *) echo "usage: mem-sampler.sh start|report" >&2; exit 2 ;;
esac
```

## B.1 Layout and procedure

```
ci-infra/
├── README.md          # hosts, going live/back, capacity, rebuild steps, what lives outside (B.5)
├── .gitattributes     # * text=auto eol=lf
├── .github/workflows/lint.yml

    ├── setup.sh       # runs on the VPS as root (B.2)
    ├── provision.sh   # runs on the admin computer (B.3)
    ├── survey.sh      # read-only look at a machine (B.4)
    └── keys/          # public SSH keys only: admin.pub, owner.pub
```

**One-time on the admin computer** (Linux, macOS, or Git Bash on Windows): install `gh` (`gh auth login` with admin rights on the repo), the VPN client, and make an admin key: `ssh-keygen -t ed25519 -f ~/.ssh/ci_admin_ed25519 -C ci-admin`. Copy its `.pub` into `ci/keys/`.

**Adding a machine `ci-N`** (also the rebuild procedure):

1. Order an OVH VPS (x86-64, the current Ubuntu LTS). **Give `ci_admin_ed25519.pub` as the SSH key in the order form**, which skips OVH's forced password change. Add a row to the README's hosts table, with reboot hour 02:00 + N UTC.
2. Look first: `ssh -i ~/.ssh/ci_admin_ed25519 ubuntu@<public-ip> 'bash -s' < ci/survey.sh`. Stop if it doesn't look fresh.
3. `CI_ADDR=<public-ip> ./ci/provision.sh ci-N base`, then reboot if it says so.
4. Create a VPN auth key (tag `tag:ci`, 1 day, not reusable) and save it in a private file: `VPN_AUTH_KEY_FILE=<file> CI_ADDR=<public-ip> ./ci/provision.sh ci-N vpn`, then delete the file.
5. Run the isolation check from the runner (section 8). It must print `blocked`.
6. `./ci/provision.sh ci-N close-public-ssh`, reboot through the VPN, and check it comes back.
7. Optional cache server: `TASK_CACHE_KEY_FILE=<file> ./ci/provision.sh ci-N task-cache`.
8. `./ci/provision.sh ci-N runner` (and `light-runner` if used).
9. `./ci/provision.sh ci-N status`, and check the runner shows `online` in `gh api repos/OWNER/REPO/actions/runners`.
10. Commit the README's updated hosts table.

## B.2 `ci/setup.sh`

```bash
#!/usr/bin/env bash
# Everything on a CI runner VPS. Runs on the VPS as root; provision.sh copies this folder over and
# calls one step. Every step can be run again and converges. It holds no secret: secrets arrive on
# stdin.
#
#   setup.sh base <ci-N>          hostname, packages, swap, SSH, firewall, updates, Docker, runner
#                                 user, job hook, hourly cleanup
#   setup.sh vpn <ci-N>           joins the tailnet with VPN_TAG; reads the auth key on stdin
#   setup.sh close-public-ssh     SSH through the VPN only; refuses unless the VPN is up
#   setup.sh open-public-ssh      undoes close-public-ssh
#   setup.sh firewall             re-applies ufw and the Docker lock; safe during a job
#   setup.sh runner <ci-N>        installs, registers and starts the CI runner; reads a registration
#                                 token on stdin (used only when the runner isn't registered yet)
#   setup.sh light-runner <ci-N>  a second, small runner for jobs of seconds; same token rule
#   setup.sh task-cache           optional shared task cache server; reads the bucket's access key
#                                 and secret key on stdin, one per line (empty: keep the current
#                                 ones). Run `runner` after it.
#   setup.sh status               prints what the other steps set up
set -euo pipefail
export DEBIAN_FRONTEND=noninteractive NEEDRESTART_MODE=a

die() { echo "setup.sh: $*" >&2; exit 1; }
[ "$(id -u)" = 0 ] || die "run as root"
HERE=$(cd "$(dirname "$0")" && pwd)
readonly HERE
[ -f "$HERE/ci.env" ] || die "no ci.env next to setup.sh"
# shellcheck source=ci.env
. "$HERE/ci.env"
case "$GH_RUNNER_URL $RUNNER_VERSION $RUNNER_SHA256" in
  *OWNER* | *X.Y.Z* | *FILL-ME*) die "fill in ci.env first" ;;
esac

readonly RUNNER_USER=github-runner
readonly RUNNER_HOME=/home/$RUNNER_USER
readonly RUNNER_DIR=$RUNNER_HOME/actions-runner
readonly LIGHT_USER=github-light
readonly LIGHT_DIR=/home/$LIGHT_USER/actions-runner
readonly HOOK=/usr/local/bin/ci-job-completed.sh    # the runner refuses a hook without .sh
readonly CLEANUP=/usr/local/bin/ci-cleanup
readonly DOCKER_FIREWALL=/usr/local/sbin/ci-docker-firewall
readonly STATE=/var/lib/ci-setup
readonly SWAP_FILE=/swapfile
readonly CACHE_ENV=/etc/ci-cache/cache.env
readonly CACHE_CONTAINER=task-cache
readonly CACHE_PORT=9310
readonly CACHE_UNIT=ci-task-cache.service
readonly KEEP_LABEL=ci.keep    # with the cache's name, a container that outlives the job hook

# Writes stdin to a file with a mode; sets CHANGED=1 when the content changed.
CHANGED=0
put() {
  local file=$1 mode=${2:-644} tmp
  tmp=$(mktemp)
  cat >"$tmp"
  if [ -f "$file" ] && cmp -s "$tmp" "$file"; then
    CHANGED=0
    chmod "$mode" "$file"
    rm -f "$tmp"
  else
    CHANGED=1
    install -D -m "$mode" "$tmp" "$file"
    rm -f "$tmp"
  fi
}

check_name() { [[ ${1:-} =~ ^ci-[1-9][0-9]*$ ]] || die "expected a host name like ci-1, got '${1:-}'"; }

base_hostname() {
  local name=$1
  put /etc/cloud/cloud.cfg.d/99-ci.cfg <<'EOF'
# setup.sh sets the hostname: cloud-init must not put the provider's name back at boot.
preserve_hostname: true
manage_etc_hosts: false
EOF
  hostnamectl set-hostname "$name"
  sed -i '/^127\.0\.1\.1[[:space:]]/d' /etc/hosts
  echo -e "127.0.1.1\t$name" >>/etc/hosts
}

base_packages() {
  apt-get update -qq
  # full-upgrade: a plain upgrade leaves a new kernel out, since it is a new package.
  apt-get -y -qq -o Dpkg::Options::=--force-confdef -o Dpkg::Options::=--force-confold full-upgrade
  # Docker from Ubuntu's own archive, so that unattended-upgrades patches it.
  apt-get -y -qq install ufw unattended-upgrades docker.io docker-buildx docker-compose-v2 jq curl \
    git ca-certificates tar gzip unzip xz-utils zstd build-essential python3 shellcheck openssl >/dev/null
}

# Swap, as GitHub's hosted runners have: a peak goes there rather than to the OOM killer.
base_swap() {
  if [ "$(stat -c %s "$SWAP_FILE" 2>/dev/null || echo 0)" != "$(numfmt --from=iec "$SWAP_SIZE")" ]; then
    if swapon --show=NAME --noheadings | grep -qxF "$SWAP_FILE"; then swapoff "$SWAP_FILE"; fi
    rm -f "$SWAP_FILE"
    (umask 077 && fallocate -l "$SWAP_SIZE" "$SWAP_FILE")
    mkswap "$SWAP_FILE" >/dev/null
  fi
  grep -qE "^$SWAP_FILE[[:space:]]" /etc/fstab || echo "$SWAP_FILE none swap sw 0 0" >>/etc/fstab
  swapon --show=NAME --noheadings | grep -qxF "$SWAP_FILE" || swapon "$SWAP_FILE"
}

base_ssh() {
  local keys
  keys=$(cat "$HERE"/keys/*.pub 2>/dev/null | grep -E '^(ssh-ed25519|ecdsa-sha2-[a-z0-9-]+|ssh-rsa) ' || true)
  [ -n "$keys" ] || die "no public key in keys/: refusing to empty authorized_keys"
  install -d -m 700 -o ubuntu -g ubuntu /home/ubuntu/.ssh
  # Exactly the keys in keys/: removing a file there revokes that key at the next run.
  printf '%s\n' "$keys" | put /home/ubuntu/.ssh/authorized_keys 600
  chown ubuntu:ubuntu /home/ubuntu/.ssh/authorized_keys
  # 00-: sshd keeps the first value it reads, and the provider's 50-cloud-init.conf allows passwords.
  put /etc/ssh/sshd_config.d/00-ci.conf <<'EOF'
PasswordAuthentication no
KbdInteractiveAuthentication no
AuthenticationMethods publickey
PermitRootLogin no
AllowUsers ubuntu
EOF
  sshd -t
  systemctl try-reload-or-restart ssh
}

base_firewall() {
  ufw default deny incoming >/dev/null
  ufw default allow outgoing >/dev/null
  # Stays closed once close-public-ssh has closed it.
  [ -e "$STATE/public-ssh-closed" ] || ufw allow 22/tcp >/dev/null
  ufw --force enable >/dev/null
}

base_updates() {
  local n=${1#ci-} hour
  hour=$(((REBOOT_BASE_HOUR + n) % 24))
  put /etc/apt/apt.conf.d/20auto-upgrades <<'EOF'
APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Unattended-Upgrade "1";
EOF
  # One machine reboots per hour, overnight (UTC): kernel fixes apply, the others keep CI up.
  put /etc/apt/apt.conf.d/52ci-unattended <<EOF
Unattended-Upgrade::Origins-Pattern { "origin=Tailscale"; };
Unattended-Upgrade::Automatic-Reboot "true";
Unattended-Upgrade::Automatic-Reboot-Time "$(printf '%02d' "$hour"):00";
EOF
  # A job that runs apt-get (browser dependencies) waits for an update instead of failing.
  put /etc/apt/apt.conf.d/90ci-lock <<'EOF'
DPkg::Lock::Timeout "600";
EOF
  systemctl enable --now unattended-upgrades >/dev/null
}

base_docker() {
  # Lock 1: a port published without an address stays on loopback, since Docker's rules go around ufw.
  put /etc/docker/daemon.json <<'EOF'
{
  "ip": "127.0.0.1",
  "log-driver": "local",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}
EOF
  local restart=$CHANGED
  systemctl enable docker >/dev/null
  if [ "$restart" = 1 ]; then systemctl restart docker; fi
  cmd_firewall
}

# Lock 2, for a port published on 0.0.0.0 on purpose: only Docker's own bridges may start traffic to
# a container. It applies at once, without restarting Docker, which would kill a running job.
cmd_firewall() {
  put "$DOCKER_FIREWALL" 755 <<'EOF'
#!/usr/bin/env bash
# Runs at each Docker start. Names no external interface, so a renamed one can't open a hole.
set -eu
for table in iptables ip6tables; do
  "$table" --wait -N DOCKER-USER 2>/dev/null || true
  # One atomic step: the chain is never empty in between.
  "$table-restore" --wait --noflush <<RULES
*filter
-F DOCKER-USER
-A DOCKER-USER -m conntrack --ctstate RELATED,ESTABLISHED -j RETURN
-A DOCKER-USER -i docker0 -j RETURN
-A DOCKER-USER -i br-+ -j RETURN
-A DOCKER-USER -j DROP
COMMIT
RULES
done
EOF
  put /etc/systemd/system/docker.service.d/10-ci-firewall.conf <<EOF
[Service]
# Before and after: containers that restart with Docker are published as it starts.
ExecStartPre=$DOCKER_FIREWALL
ExecStartPost=$DOCKER_FIREWALL
EOF
  systemctl daemon-reload
  "$DOCKER_FIREWALL"
  # The VPN's own rules would accept tailnet traffic ahead of ufw: with them off, ufw decides.
  if command -v tailscale >/dev/null && tailscale ip -4 >/dev/null 2>&1; then
    tailscale set --netfilter-mode=off
  fi
  echo "Firewall set."
}

base_runner_user() {
  id "$RUNNER_USER" >/dev/null 2>&1 || useradd --create-home --shell /bin/bash "$RUNNER_USER"
  usermod --append --groups docker "$RUNNER_USER"
  # The docker group is worth root anyway; GitHub's hosted runners have passwordless sudo too, and
  # steps such as `playwright install --with-deps` need it. Acceptable only because this machine
  # holds no secret worth stealing.
  if [ "$RUNNER_SUDO" = yes ]; then
    put /etc/sudoers.d/90-github-runner 440 <<<"$RUNNER_USER ALL=(ALL) NOPASSWD:ALL"
    visudo -cf /etc/sudoers.d/90-github-runner >/dev/null
  else
    rm -f /etc/sudoers.d/90-github-runner
  fi
}

base_hook() {
  # Stands in for --ephemeral: the next job starts clean, with no GitHub credential on the VPS to
  # register again with. Keeps _work/_tool, the Docker images and the package and browser caches.
  put "$HOOK" 755 <<EOF
#!/usr/bin/env bash
# Runs as $RUNNER_USER after every job (ACTIONS_RUNNER_HOOK_JOB_COMPLETED) and before the runner
# starts (its unit's ExecStartPre). The runner takes one job at a time, so every container but the
# machine's own cache server, and every process working in _work, belongs to the job that ended.
# The runner runs a hook with bash -e, and a failing hook fails the job: this one never fails.
set +e -u
shopt -s dotglob nullglob
work=$RUNNER_DIR/_work
containers=\$(docker ps --all --format '{{.ID}} {{.Names}} {{.Label "$KEEP_LABEL"}}' |
  awk '!(\$2 == "$CACHE_CONTAINER" && \$3 != "") {print \$1}')
if [ -n "\$containers" ]; then docker rm --force --volumes \$containers >/dev/null 2>&1; fi
docker network prune --force >/dev/null 2>&1
docker volume prune --all --force >/dev/null 2>&1

# What the job left running (a dev server of a cancelled test...). The runner finds those by
# RUNNER_TRACKING_ID, which a process can drop. So a process goes if it works in _work (or a deleted
# folder of it) or runs a program from it. The runner and this hook are spared by name and ancestry.
spared=" "
pid=\$\$
while [ "\$pid" -gt 1 ] 2>/dev/null; do
  spared="\$spared\$pid "
  pid=\$(ps -o ppid= -p "\$pid" | tr -d ' ')
done
for _ in 1 2 3; do
  killed=0
  for pid in \$(pgrep -u $RUNNER_USER); do
    case "\$spared" in *" \$pid "*) continue ;; esac
    case \$(cat "/proc/\$pid/comm") in runsvc.sh | Runner.Listener | Runner.Worker) continue ;; esac
    case "\$(readlink "/proc/\$pid/cwd")/ \$(readlink "/proc/\$pid/exe")" in
      "\$work/"* | *" \$work/"*) kill -KILL "\$pid" && killed=1 ;;
    esac
  done 2>/dev/null
  [ "\$killed" = 1 ] || break
  sleep 1
done

# _work/<repo>/<repo>; folders starting with _ are the runner's own (tool cache, temp...).
for workspace in "\$work"/[!_]*/*/; do
  sudo -n find "\$workspace" -mindepth 1 -delete 2>/dev/null || find "\$workspace" -mindepth 1 -delete
done
exit 0
EOF

  put "$CLEANUP" 755 <<EOF
#!/usr/bin/env bash
# Hourly, as root (ci-cleanup.timer). Everything it removes can be downloaded again.
set -u
disk_used() { df --output=pcent / | tail -n 1 | tr -dc 0-9; }
docker container prune --force --filter until=6h >/dev/null 2>&1   # stopped ones only
docker builder prune --force --filter until=168h >/dev/null 2>&1
journalctl --quiet --vacuum-size=500M
find "$RUNNER_DIR/_diag" "$LIGHT_DIR/_diag" -type f -mtime +14 -delete 2>/dev/null
apt-get clean
# Over 70%, the caches go too, unless a job is using them: the next hour tries again.
if [ "\$(disk_used)" -ge 70 ] && ! pgrep -u $RUNNER_USER -x Runner.Worker >/dev/null; then
  echo "Disk at \$(disk_used)%: clearing the caches."
  docker image prune --all --force >/dev/null 2>&1
  if pgrep -u $RUNNER_USER -x Runner.Worker >/dev/null; then exit 0; fi
  rm -rf "$RUNNER_DIR/_work/_tool" "$RUNNER_HOME/.cache" "$RUNNER_HOME/.npm" "$RUNNER_HOME/.local/share/pnpm"
  echo "Disk at \$(disk_used)%."
fi
exit 0
EOF

  put /etc/systemd/system/ci-cleanup.service <<EOF
[Unit]
Description=Keep the CI runner's disk from filling up
After=docker.service

[Service]
Type=oneshot
ExecStart=$CLEANUP
EOF
  put /etc/systemd/system/ci-cleanup.timer <<'EOF'
[Unit]
Description=Hourly CI runner cleanup

[Timer]
OnCalendar=hourly
RandomizedDelaySec=300
Persistent=true

[Install]
WantedBy=timers.target
EOF
  systemctl daemon-reload
  systemctl enable --now ci-cleanup.timer >/dev/null 2>&1
}

cmd_base() {
  local name=${1:-}
  check_name "$name"
  base_hostname "$name"
  base_packages
  base_swap
  base_ssh
  base_firewall
  base_updates "$name"
  base_docker
  base_runner_user
  base_hook
  [ ! -e /var/run/reboot-required ] || echo "A reboot is needed for updates that were just installed."
  echo "base done on $name"
}

cmd_vpn() {
  local name=${1:-} key_file
  check_name "$name"
  key_file=$(mktemp)
  # shellcheck disable=SC2064
  trap "rm -f '$key_file'" EXIT
  cat >"$key_file"
  if ! command -v tailscale >/dev/null; then
    # shellcheck disable=SC1091
    . /etc/os-release
    curl -fsSL "https://pkgs.tailscale.com/stable/ubuntu/$VERSION_CODENAME.noarmor.gpg" \
      -o /usr/share/keyrings/tailscale-archive-keyring.gpg
    curl -fsSL "https://pkgs.tailscale.com/stable/ubuntu/$VERSION_CODENAME.tailscale-keyring.list" \
      -o /etc/apt/sources.list.d/tailscale.list
    apt-get update -qq
    apt-get -y -qq install tailscale >/dev/null
  fi
  systemctl enable --now tailscaled >/dev/null
  # With the VPN's own rules off, this is what lets SSH in: it comes first.
  ufw allow in on tailscale0 to any port 22 proto tcp >/dev/null
  if tailscale ip -4 >/dev/null 2>&1; then
    echo "$name is already on the tailnet."
    tailscale set --netfilter-mode=off
  else
    [ -s "$key_file" ] || die "no auth key on stdin"
    tailscale up --auth-key="file:$key_file" --hostname="$name" --advertise-tags="$VPN_TAG" \
      --accept-dns=false --accept-routes=false --ssh=false --netfilter-mode=off
  fi
  echo "vpn done on $name: $(tailscale ip -4)"
}

# Reads ufw's whole output first (grep stopping early would break its pipe). With ufw off, it's open.
public_ssh_open() {
  local rules
  rules=$(ufw status)
  grep -q '^Status: active' <<<"$rules" || return 0
  grep -qE '^22/tcp( \(v6\))? +ALLOW' <<<"$rules"
}

cmd_close_public_ssh() {
  tailscale ip -4 >/dev/null 2>&1 || die "the VPN is not up: public SSH stays open"
  ufw allow in on tailscale0 to any port 22 proto tcp >/dev/null
  ufw delete allow 22/tcp >/dev/null 2>&1 || true
  ! public_ssh_open || die "ufw still allows public SSH"
  install -d "$STATE"
  touch "$STATE/public-ssh-closed"
  echo "Public SSH closed."
}

cmd_open_public_ssh() {
  ufw allow 22/tcp >/dev/null
  rm -f "$STATE/public-ssh-closed"
  echo "Public SSH open."
}

# The CI runner's memory limits, in MiB: what the machine has, less what the rest needs.
memory_limits() {
  local total max
  total=$(awk '/^MemTotal:/ {printf "%d", $2 / 1024}' /proc/meminfo)
  max=${RUNNER_MEMORY_MAX_MIB:-$((total - RESERVED_MIB))}
  echo "$((max - 512)) $max"
}

# What the unit does when a job runs out of memory, and after any exit. svc.sh writes the unit; its
# drop-ins are setup.sh's alone, so none made by hand outlives a rebuild.
runner_unit() {
  local unit=$1 dropins=/etc/systemd/system/$1.d high max
  read -r high max < <(memory_limits)
  put "$dropins/10-ci.conf" <<EOF
[Unit]
# The hook below removes the last job's containers, so Docker comes first, at boot too.
Wants=docker.service
After=docker.service

[Service]
# Above MemoryHigh the job slows down and swaps; at MemoryMax the kernel kills one of its processes.
# sshd, dockerd and the VPN keep their memory. Containers live outside, in Docker's own cgroups.
MemoryHigh=${high}M
MemoryMax=${max}M
# Then that job fails alone; systemd's default would stop the whole runner.
OOMPolicy=continue
# Back after any exit, whatever its code: the runner's script can exit 0 when its listener stops.
Restart=always
RestartSec=15
# Before each start: what a runner that died mid-job left behind. Nothing else runs as this user.
ExecStartPre=-/usr/bin/pkill -KILL -u $RUNNER_USER
ExecStartPre=-$HOOK
EOF
  find "$dropins" -mindepth 1 -maxdepth 1 ! -name 10-ci.conf -printf 'Removed %p\n' -delete
  systemctl daemon-reload
}

# The runner's files at the pinned version, checked against its SHA-256, once: it updates itself.
runner_files() {
  local user=$1 dir=$2 tarball
  if [ ! -x "$dir/config.sh" ]; then
    tarball=$(mktemp)
    curl -fsSL -o "$tarball" \
      "https://github.com/actions/runner/releases/download/v$RUNNER_VERSION/actions-runner-linux-x64-$RUNNER_VERSION.tar.gz"
    echo "$RUNNER_SHA256  $tarball" | sha256sum --check --quiet
    install -d -o "$user" -g "$user" "$dir"
    tar -xzf "$tarball" -C "$dir" --no-same-owner
    chown -R "$user:$user" "$dir"
    rm -f "$tarball"
  fi
  "$dir/bin/installdependencies.sh" >/dev/null
}

register() { # register <user> <dir> <name> <labels> <token>
  local user=$1 dir=$2 name=$3 labels=$4 token=$5
  [ ! -f "$dir/.runner" ] || return 0
  [ -n "$token" ] || die "no registration token on stdin"
  # Not --ephemeral: registering again would need a long-lived GitHub credential here.
  (cd "$dir" && ACTIONS_RUNNER_INPUT_TOKEN=$token runuser -u "$user" -- \
    ./config.sh --unattended --url "$GH_RUNNER_URL" --name "$name" --labels "$labels" \
    --work _work --replace)
}

cmd_runner() {
  local name=${1:-} token
  check_name "$name"
  token=$(cat)
  id "$RUNNER_USER" >/dev/null 2>&1 || die "run setup.sh base first"
  runner_files "$RUNNER_USER" "$RUNNER_DIR"
  # Its own name as a second label: the capacity test targets one machine with it.
  register "$RUNNER_USER" "$RUNNER_DIR" "$name" "$RUNNER_LABEL,$name" "$token"
  unset token
  cd "$RUNNER_DIR"

  # The runner's environment, which every job inherits. Only a change restarts it, after its job.
  local restart=0 line lines=("ACTIONS_RUNNER_HOOK_JOB_COMPLETED=$HOOK" "TASK_CONCURRENCY=$TASK_CONCURRENCY") stale=()
  if [ -f "$CACHE_ENV" ]; then
    lines+=("TURBO_API=http://127.0.0.1:$CACHE_PORT" "TURBO_TEAM=$CACHE_TEAM"
      "TURBO_TOKEN=$(sed -n 's/^TURBO_TOKEN=//p' "$CACHE_ENV")")
  else
    stale=(TURBO_API TURBO_TEAM TURBO_TOKEN)
  fi
  touch .env
  for line in "${lines[@]}"; do
    if ! grep -qxF "$line" .env; then
      sed -i "/^${line%%=*}=/d" .env
      echo "$line" >>.env
      restart=1
    fi
  done
  for line in "${stale[@]}"; do
    if grep -q "^$line=" .env; then sed -i "/^$line=/d" .env; restart=1; fi
  done
  chown "$RUNNER_USER:$RUNNER_USER" .env
  [ -f .service ] || ./svc.sh install "$RUNNER_USER"
  runner_unit "$(cat .service)"
  if [ "$restart" = 1 ]; then
    while pgrep -u "$RUNNER_USER" -x Runner.Worker >/dev/null; do
      echo "A job is running: waiting for it to end before the restart."
      sleep 20
    done
    ./svc.sh stop >/dev/null 2>&1 || true
  fi
  ./svc.sh start
  echo "runner done on $name"
}

# A small runner for jobs of seconds that would otherwise wait behind a long CI job. Its own user,
# with neither Docker nor sudo: its jobs must read no repository code.
cmd_light_runner() {
  local name=${1:-} token unit dropins

  token=$(cat)

  unset token
  cd "$LIGHT_DIR"
  [ -f .service ] || ./svc.sh install "$LIGHT_USER"
  unit=$(cat .service)
  dropins=/etc/systemd/system/$unit.d
  put "$dropins/10-ci.conf" <<EOF
[Service]
MemoryHigh=384M
MemoryMax=512M
OOMPolicy=continue
Restart=always
RestartSec=15
ExecStartPre=-/usr/bin/pkill -KILL -u $LIGHT_USER
EOF
  find "$dropins" -mindepth 1 -maxdepth 1 ! -name 10-ci.conf -printf 'Removed %p\n' -delete

}

# Optional: a Turborepo-compatible remote cache server on loopback, storing in the S3 bucket that
# every runner shares. The bucket's lifecycle rule deletes entries after 14 days.
cmd_task_cache() {
  [ -n "$CACHE_IMAGE" ] && [ -n "$CACHE_BUCKET" ] || die "set CACHE_IMAGE and CACHE_BUCKET in ci.env"
  local access="" secret="" token=""
  IFS= read -r access || true
  IFS= read -r secret || true
  access=${access//[$'\r\n ']/}
  secret=${secret//[$'\r\n ']/}
  if [ -f "$CACHE_ENV" ]; then
    [ -n "$access" ] || access=$(sed -n 's/^AWS_ACCESS_KEY_ID=//p' "$CACHE_ENV")
    [ -n "$secret" ] || secret=$(sed -n 's/^AWS_SECRET_ACCESS_KEY=//p' "$CACHE_ENV")
    token=$(sed -n 's/^TURBO_TOKEN=//p' "$CACHE_ENV")
  fi
  [ -n "$access" ] && [ -n "$secret" ] || die "no access key and secret key on stdin"
  # Guards only the loopback server; jobs on this machine get it through the runner's .env.
  [ -n "$token" ] || token=$(openssl rand -hex 32)
  put "$CACHE_ENV" 600 <<EOF
STORAGE_PROVIDER=s3
STORAGE_PATH=$CACHE_BUCKET
S3_ENDPOINT=$CACHE_ENDPOINT
AWS_REGION=$CACHE_REGION
AWS_ACCESS_KEY_ID=$access
AWS_SECRET_ACCESS_KEY=$secret
TURBO_TOKEN=$token
LOG_LEVEL=warn
EOF
  local restart=$CHANGED
  unset access secret token
  put "/etc/systemd/system/$CACHE_UNIT" <<EOF
[Unit]
Description=Shared task cache for CI jobs, on 127.0.0.1:$CACHE_PORT
Requires=docker.service
After=docker.service

[Service]
ExecStartPre=-/usr/bin/docker rm --force $CACHE_CONTAINER
ExecStart=/usr/bin/docker run --rm --name $CACHE_CONTAINER --label $KEEP_LABEL=1 \\
  --publish 127.0.0.1:$CACHE_PORT:3000 --env-file $CACHE_ENV --memory 512m $CACHE_IMAGE
ExecStop=/usr/bin/docker stop $CACHE_CONTAINER
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target docker.service
EOF
  [ "$CHANGED" = 0 ] || restart=1
  docker pull --quiet "$CACHE_IMAGE" >/dev/null
  systemctl daemon-reload
  systemctl reenable "$CACHE_UNIT" >/dev/null 2>&1
  if [ "$restart" = 1 ]; then systemctl restart "$CACHE_UNIT"; else systemctl start "$CACHE_UNIT"; fi

  # Proves the server answers and reaches the bucket: write an entry, read it back.
  local api=http://127.0.0.1:$CACHE_PORT auth probe got
  auth="Authorization: Bearer $(sed -n 's/^TURBO_TOKEN=//p' "$CACHE_ENV")"
  for _ in $(seq 30); do
    curl -fsS -H "$auth" "$api/v8/artifacts/status" >/dev/null 2>&1 && break
    sleep 1
  done
  probe="setup-probe-$(hostname)"
  curl -fsS -X PUT -H "$auth" -H 'Content-Type: application/octet-stream' --data-binary "$probe" \
    "$api/v8/artifacts/$probe?slug=$CACHE_TEAM" >/dev/null || die "the cache doesn't take an entry"
  got=$(curl -fsS -H "$auth" "$api/v8/artifacts/$probe?slug=$CACHE_TEAM") || die "the cache doesn't give it back"
  [ "$got" = "$probe" ] || die "the cache gave back something else"
  echo "task-cache done on $(hostname): run 'runner' next so jobs use it"
}

cmd_status() {
  echo "host: $(hostname)  os: $(. /etc/os-release; echo "$PRETTY_NAME")  kernel: $(uname -r)"
  echo "reboot needed: $([ -e /var/run/reboot-required ] && echo yes || echo no)"
  echo "-- sshd"; sshd -T | grep -E '^(permitrootlogin|passwordauthentication|kbdinteractiveauthentication|authenticationmethods|allowusers) '
  echo "-- ufw"; ufw status verbose | grep -vE '^$'
  echo "-- updates"; systemctl is-enabled unattended-upgrades; grep -h Reboot-Time /etc/apt/apt.conf.d/52ci-unattended
  echo "-- docker"; docker --version; docker ps --all --format '{{.Names}} {{.Status}}'
  iptables -S DOCKER-USER || true
  echo "-- cleanup"; systemctl is-active ci-cleanup.timer || true
  echo "-- task cache"; systemctl is-active "$CACHE_UNIT" 2>/dev/null || echo "not set up"
  echo "-- vpn"; if command -v tailscale >/dev/null; then tailscale ip -4 || true; else echo "not installed"; fi
  echo "-- runners"; systemctl list-units --no-legend --no-pager 'actions.runner.*' || true
  if [ -f "$RUNNER_DIR/.service" ]; then
    systemctl show "$(cat "$RUNNER_DIR/.service")" \
      --property=Restart,OOMPolicy,MemoryHigh,MemoryMax,NRestarts,DropInPaths |
      awk -F= '/^Memory/ && $2 ~ /^[0-9]+$/ {$2 = $2 / 1048576 "M"} {print $1 "=" $2}'
    grep -E '^TASK_CONCURRENCY=' "$RUNNER_DIR/.env" || true
  fi
  echo "-- swap"; swapon --show=NAME,SIZE,USED --noheadings | grep . || echo "off"
  echo "-- listening"; ss -tln | awk 'NR>1 {print $4}' | sort -u | tr '\n' ' '; echo
  echo "-- disk"; df -h / | tail -n 1
}

command=${1:-}
[ $# -eq 0 ] || shift
case "$command" in
  base) cmd_base "$@" ;;
  vpn) cmd_vpn "$@" ;;
  close-public-ssh) cmd_close_public_ssh ;;
  open-public-ssh) cmd_open_public_ssh ;;
  firewall) cmd_firewall ;;
  runner) cmd_runner "$@" ;;
  light-runner) cmd_light_runner "$@" ;;
  task-cache) cmd_task_cache ;;
  status) cmd_status ;;
  *) die "unknown command '$command'" ;;
esac
```

## B.3 `ci/provision.sh`

```bash
#!/usr/bin/env bash
# Runs on the admin computer (Linux, macOS, or Git Bash on Windows): copies setup.sh, ci.env and
# keys/ to a runner VPS, then runs one step of setup.sh there as root.
#
#   CI_ADDR=<public-ip> ./provision.sh ci-N base           before the VPS is on the VPN
#   VPN_AUTH_KEY_FILE=<file> CI_ADDR=<public-ip> ./provision.sh ci-N vpn
#   ./provision.sh ci-N close-public-ssh|open-public-ssh|firewall|status
#   ./provision.sh ci-N runner|light-runner                gets a fresh registration token via gh
#   TASK_CACHE_KEY_FILE=<file> ./provision.sh ci-N task-cache
#
# Secrets come from files or pipes, never from the command line: they stay out of shell history and ps.
set -euo pipefail
here=$(cd "$(dirname "$0")" && pwd)
# shellcheck source=ci.env
. "$here/ci.env"
key=${CI_ADMIN_KEY:-$HOME/.ssh/ci_admin_ed25519}
readonly remote=/usr/local/lib/ci-setup
die() { echo "provision.sh: $*" >&2; exit 1; }

name=${1:?usage: provision.sh <ci-N> <step>}
step=${2:?usage: provision.sh <ci-N> <step>}
[[ $name =~ ^ci-[1-9][0-9]*$ ]] || die "expected ci-N, got '$name'"
addr=${CI_ADDR:-$(tailscale ip -4 "$name" 2>/dev/null || true)}
[ -n "$addr" ] || die "can't find $name on the VPN: set CI_ADDR to its public IP"
# `base` makes authorized_keys exactly keys/: the key this script logs in with must be there.
grep -qF "$(awk '{print $2}' "$key.pub")" "$here"/keys/*.pub || die "$key.pub is not in keys/"

on_vps() {
  ssh -i "$key" -o IdentitiesOnly=yes -o BatchMode=yes -o ConnectTimeout=20 \
    -o StrictHostKeyChecking=accept-new "ubuntu@$addr" "$@"
}

# Takes the runner out of CI for a step that may restart it, and gives it back after, even when the
# step fails: without its label GitHub sends it no new job, and we wait for the one it runs.
drained() {
  local id busy
  id=$(gh api "$GH_RUNNER_SCOPE/actions/runners?per_page=100" --jq ".runners[] | select(.name == \"$name\") | .id")
  if [ -z "$id" ]; then "$@"; return; fi
  if [ "$(gh api "$GH_RUNNER_SCOPE/actions/runners/$id" --jq "[.labels[].name] | index(\"$RUNNER_LABEL\") != null")" = true ]; then
    gh api -X DELETE "$GH_RUNNER_SCOPE/actions/runners/$id/labels/$RUNNER_LABEL" >/dev/null
    # shellcheck disable=SC2064
    trap "gh api -X POST $GH_RUNNER_SCOPE/actions/runners/$id/labels -f 'labels[]=$RUNNER_LABEL' >/dev/null" EXIT
  fi
  while :; do
    busy=$(gh api "$GH_RUNNER_SCOPE/actions/runners/$id" --jq .busy) || die "GitHub didn't answer"
    [ "$busy" = true ] || break
    echo "$name is running a job: waiting for it to end."
    sleep 20
  done
  "$@"
}

# Copied whole each time, so the VPS runs exactly what this folder holds.
tar -C "$here" -cf - setup.sh ci.env keys |
  on_vps "sudo rm -rf $remote.new && sudo mkdir -p $remote.new && sudo tar -xf - -C $remote.new --no-same-owner && sudo rm -rf $remote && sudo mv $remote.new $remote"
setup="sudo bash $remote/setup.sh"

token() { gh api -X POST "$GH_RUNNER_SCOPE/actions/runners/registration-token" --jq .token; }  # 1 hour, single use

case "$step" in
  base) on_vps "$setup base $name" </dev/null ;;
  close-public-ssh | open-public-ssh | firewall | status) on_vps "$setup $step" </dev/null ;;
  vpn) on_vps "$setup vpn $name" <"${VPN_AUTH_KEY_FILE:?set VPN_AUTH_KEY_FILE}" ;;
  runner)
    install_runner() { token | on_vps "$setup runner $name"; }
    drained install_runner
    ;;
  light-runner) token | on_vps "$setup light-runner $name" ;;   # jobs of seconds: not drained
  task-cache) on_vps "$setup task-cache" <"${TASK_CACHE_KEY_FILE:?set TASK_CACHE_KEY_FILE}" ;;
  *) die "unknown step '$step'" ;;
esac
```

## B.6 VPN policy (Tailscale example)

Replace the default allow-all policy:

```json
{
  "groups": { "group:admins": ["<owner-login>"] },
  "tagOwners": { "tag:ci": ["group:admins"] },
  "grants": [
    { "src": ["group:admins"], "dst": ["tag:ci"], "ip": ["*"] },
    { "src": ["group:admins"], "dst": ["autogroup:self"], "ip": ["*"] }
  ],
  "tests": [
    { "src": "<owner-login>", "accept": ["tag:ci:22"] },
    { "src": "tag:ci", "deny": ["<owner-login>:22", "tag:ci:22"] }
  ]
}
```

No grant may have `tag:ci` as its source, and none may use `"src": ["*"]`.
